# OQ-002 — Какие codecs и containers реально возвращаются?

## Context

От набора кодеков/контейнеров зависят AudioVariant, выбор библиотеки тегов, валидация и правила качества.

## Decision needed

Зафиксировать фактические codec/container/bitrate/lossless по разным аккаунтам и трекам.

## Resolution

В STEP-005 2026-10-08 исследован один аккаунт с подпиской и треки `2224197`, `150217442`, `151910374`. Для каждого `/download-info` вернул полные (`preview=false`) MP3-варианты 192 и 320 kbps. Доступность треков подтверждена API; префиксы до 1 MiB прочитаны с `206`, определитель сигнатуры согласован с MP3. Точные фактические битрейты bytes не измерялись: 192/320 — поля API, не результат независимого анализа всего файла.

`/get-file-info` на запрос lossless вернул для `2224197` `aac-mp4`, 256 kbps, `isLossless=false`, а для `150217442` и `151910374` — `flac-mp4`, bitrate 0, `isLossless=true`. Все три ответа сообщают `transport=encraw`, наличие ключа и ссылок; их значения не сохранены. Нулевой bitrate не трактуется как измеренный битрейт FLAC. Для этого пути явный `preview=false` не подтверждён, поэтому префиксы/расшифровка пропущены, контейнер и lossless современного потока подтверждены только полями API, а не bytes. Подписка не гарантирует FLAC: есть наблюдаемый AAC fallback при запросе lossless.

Evidence: [таблица и ограничения](../research/yandex-api-spike.md#варианты-аудио), [вывод](../research/yandex-api-spike-output.jsonl). Другие аккаунты/регионы и все codecs не покрыты. Будущий provider ADR должен различать поля API, доказанные сигнатуры, неустановленный preview и отказ от неподтверждённого полного варианта; правила high/normal остаются решением владельца OQ-011.
