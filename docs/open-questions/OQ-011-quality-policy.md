# OQ-011 — Правила для high/normal и fallback при недоступной настройке качества

## Context

Пресеты Best Available, Lossless, High и Normal требуют явного определения: как High и Normal соотносятся с реальными вариантами и что делать, если выбранная настройка недоступна (отказ с QualityUnavailableError или снижение качества). Фиксированные соответствия (Premium = FLAC, High = 320 kbps) запрещены. Ответ меняет acceptance resolver и поведение CLI/UI.

## Decision needed

Определить правила ранжирования вариантов для `high`/`normal` на основании evidence OQ-002 и политику при недоступной настройке (ошибка или документированное снижение) — решение владельца продукта.

## Resolution

Частичное решение владельца продукта (2026-10-04): при недоступности выбранной настройки (`lossless`, `high`, `normal`) трек получает `QualityUnavailableError` без тихого снижения качества, остальные треки job продолжаются; `best` выбирает лучший из доступных вариантов. Остаётся открытым: правила ранжирования, определяющие `high` и `normal` на основании фактических вариантов (нужны данные исследования API по OQ-002).


Результаты исследования API (2026-10-08): на трёх треках аккаунта с подпиской подтверждены полные MP3 192/320 kbps. Современный API сообщил AAC 256 и FLAC в encraw, но их preview/bytes не подтверждены; запрос lossless может фактически вернуть AAC. [Наблюдения и ограничения](OQ-002-codecs.md).

Для решения владельца предлагаются два варианта внутри сопоставимой группы codec:

1. `high` — максимальный доступный подтверждённый lossy-вариант; `normal` — минимальный. В текущей MP3-выборке это 320/192, но числа не становятся универсальными порогами. Если есть один вариант, оба пресета выбирают его.
2. `high` — максимальный доступный подтверждённый lossy-вариант; `normal` — следующий более низкий отличающийся вариант. В текущей выборке тоже 320/192; если низшего варианта нет, `normal` даёт `QualityUnavailableError`.

Сравнение разных codec и включение современных вариантов после подтверждения полноты должны быть явно согласованы; AAC 256 нельзя автоматически ранжировать по числу kbps относительно MP3. Ни один вариант правила пока не принят. Уже принятое отсутствие тихого fallback сохраняется, OQ-011 остаётся open.

Решение владельца продукта (2026-10-10), закрывает OQ-011 (из предложенных вариантов принят первый, а кодеки не сравниваются):

- `high` — вариант с максимальным bitrate среди поддерживаемых подтверждённых lossy-вариантов сопоставимой группы; `normal` — с минимальным в той же группе. Если вариант один, оба пресета выбирают его. Числовые пороги (320/192 и т. п.) в код не зашиваются.
- Сопоставимая группа — один и тот же codec. Bitrate разных codec (например, AAC 256 и MP3 320) не сравнивается. Если подтверждённых lossy-вариантов нескольких codec несколько, группу выбирает внедряемое ранжирование codec (его параметры обосновываются исследованием аудиометаданных); без него берётся codec первого подходящего lossy-варианта в порядке provider.
- Те же правила группы применяются к lossy-ветке `best`; lossless по-прежнему предпочтительнее lossy.
- Политика недоступной настройки не меняется: `QualityUnavailableError` без тихого снижения качества.
