# OQ-001 — Какой auth flow стабильно поддерживается текущим API?

## Context

Авторизация должна использовать OAuth / Device Authorization без передачи пароля приложению. Поддерживаемый flow определяется возможностями API; требования к нему и хранению токена описаны в REQ-001, REQ-002 и ADR-010.

## Decision needed

Определить фактически поддерживаемый и стабильный flow авторизации и его ограничения (срок жизни токена, refresh).

## Resolution

2026-10-08 в исследовании API на собственном аккаунте с подпиской подтверждён OAuth Device Authorization: выдача Device Code (`200`), подтверждение владельцем через выданный сервером адрес на `ya.ru`, получение токена (`200`) и идентификация аккаунта через `Client.init`/account status (`200`). Пароль приложение не запрашивает; токен не сохраняется. Device Code действует 300 секунд, interval 5 секунд. Access-token ответ сообщает `expiresIn=31536000` и наличие refresh token; фактическое годовое истечение не наблюдалось.

`refreshAccessToken` на уже авторизованном Client вернул `401`; после отказа исходный access token успешно использовался для чтения каталога. Причина отказа не установлена, поддержка refresh в других условиях не отвергнута. Библиотека сохраняет Authorization в transport при установке, поэтому после выдачи токена research вызывает `client.request.setAuthorization`; одной смены `client.token` недостаточно. Product flow/storage должен принять ADR-009/010 с этими ограничениями, а не предполагать работающий refresh.

Подтверждён один flow и один аккаунт; повторное использование после истечения и другие OAuth grants не исследованы.
