# Yandex Music Downloader — минимальный брендбук

> Версия: 0.1  
> Назначение: зафиксировать визуальные правила desktop-приложения до реализации React + MUI UI; палитра, типографика, spacing и доступность также применяются к приватной browser-странице Device Authorization (STEP-041).

## 1. Позиционирование

Yandex Music Downloader — утилитарное desktop-приложение для управления загрузками музыки.

Визуальный язык должен быть:

- современным;
- спокойным;
- технологичным;
- нейтральным;
- хорошо читаемым при длительной работе;
- близким к Material Design, без попытки копировать интерфейс Яндекс Музыки.

Приложение использует **собственную визуальную идентичность**. Фирменные цвета и логотипы Яндекса не должны использоваться как основа бренда приложения.

---

## 2. Логотип и знак

Минимальный знак:

- квадрат со скруглением;
- жёлтый фон;
- тёмная стилизованная музыкальная нота;
- белый круг с тёмной стрелкой загрузки;
- без использования официального логотипа Яндекса.

Файл иконки - `./icon.png`.

### Рекомендуемые варианты

1. **App icon** — знак без текста.
2. **Horizontal lockup** — знак + `Yandex Music Downloader`.
3. **Compact lockup** — знак + `Music Downloader`, если полное название не помещается.

### Safe area

Вокруг знака оставлять свободное пространство не менее `0.25 ×` ширины иконки.

## 5. Сетка и spacing

Используется базовый шаг MUI:

```text
1 unit = 8 px
```

Основные значения:

| Token | Значение |
|---|---:|
| `xs` | 4 px |
| `sm` | 8 px |
| `md` | 16 px |
| `lg` | 24 px |
| `xl` | 32 px |
| `2xl` | 48 px |

### Desktop layout

- Sidebar: `220–240 px`.
- Основной контент: fluid.
- Максимальная рабочая ширина основных форм: `1200–1400 px`.
- Внутренние padding карточек: `16–24 px`.
- Gap между логическими секциями: `24 px`.

## 7. Тени

Интерфейс должен быть преимущественно плоским.

Использовать:

- border для большинства карточек;
- лёгкую тень только для dialog, menu, popover;
- никаких тяжёлых декоративных теней.

Пример:

```css
box-shadow: 0 8px 24px rgba(15, 23, 42, 0.08);
```

---

## 8. Иконки

Использовать:

```text
@mui/icons-material
```

Правила:

- размер по умолчанию: `20 px`;
- в sidebar: `20 px`;
- inline action: `18–20 px`;
- крупный empty state: `40–48 px`;
- одинаковая stroke/visual weight внутри одного блока.

## 10. Buttons

### Primary

Использовать для главного действия на экране:

- `Скачать`;
- `Добавить в загрузки`;
- `Анализировать`.

### Outlined

Для вторичных действий:

- `Выбрать папку`;
- `Повторить`;
- `Открыть папку`.

### Text

Для малозначимых действий:

- `Отмена`;
- `Очистить фильтр`;
- `Подробнее`.

На одной форме должен быть только один визуально доминирующий primary action.

## 11. Поля ввода

Высота:

```text
40–44 px
```

Основное поле URL допускается делать выше и заметнее.

Placeholder должен объяснять ожидаемый формат:

```text
Вставьте ссылку на трек, альбом или плейлист Яндекс Музыки
```

Ошибки показывать через стандартный MUI helper text.

## 12. Статусы загрузки

### Статусы

| Состояние | Цвет |
|---|---|
| Queued | `text.secondary` |
| Resolving | `info.main` |
| Downloading | `primary.main` |
| Paused | `warning.main` |
| Completed | `secondary.main` |
| Failed | `error.main` |
| Cancelled | `text.secondary` |

### Progress

- Для текущего трека использовать `LinearProgress`.
- Для job показывать одновременно:
  - процент;
  - `N / total`;
  - размер;
  - скорость, если она достоверно известна.
- Не показывать ETA, если расчёт нестабилен.

## 14. Основные экраны

В UI-макетах должны быть зафиксированы как минимум:

1. **Главная — пустое состояние**
   - URL input;
   - CTA `Анализировать`;
   - drop zone;
   - примеры поддерживаемых ссылок.

2. **Результат анализа — трек**
   - обложка;
   - название;
   - артист;
   - альбом;
   - длительность;
   - доступные варианты качества;
   - output folder;
   - metadata/cover options;

3. **Результат анализа — плейлист**
   - обложка;
   - название;
   - владелец;
   - количество треков;
   - длительность;
   - preview списка;
   - настройки качества;
   - `.m3u8`;
   - CTA загрузки всего плейлиста.

4. **Загрузки**
   - очередь;
   - активные;
   - завершённые;
   - ошибки;
   - progress;
   - pause/resume;
   - retry;
   - cancel.

5. **История**
   - поиск;
   - фильтры;
   - тип;
   - число треков;
   - размер;
   - дата;
   - контекстное меню.

6. **Настройки**
   - output directory;
   - concurrency;
   - качество по умолчанию;
   - metadata;
   - cover;
   - `.m3u8`;
   - поведение после завершения.

7. **Аккаунт**
   - статус авторизации;
   - имя / account identifier;

8. **Диагностика**
   - runtime;

## 15. Empty states

Empty state должен:

- кратко объяснять, что делать дальше;
- содержать один primary action либо одно главное поле;
- не быть декоративно перегруженным;
- использовать иконку или простую иллюстрацию.

Пример:

```text
Вставьте ссылку на трек, альбом или плейлист
Мы определим тип контента и покажем доступные параметры загрузки.
```

---

## 16. Ошибки

Ошибки должны быть предметными.

Плохо:

```text
Something went wrong
```

Хорошо:

```text
Не удалось получить информацию о треке.
Проверьте соединение и повторите попытку.
```

Для `API_CHANGED`:

```text
API Яндекс Музыки изменился.
Текущая версия приложения не поддерживает новый формат ответа.
```

Для inline-ошибок использовать `Alert severity="error"` или helper text.

## 19. Accessibility

Минимальные требования:

- контраст текста соответствует WCAG AA;
- интерфейс полностью доступен с клавиатуры;
- focus state всегда видим;
- icon-only buttons имеют `aria-label`;
- цвет не должен быть единственным способом передачи статуса;
- progress и status должны иметь текстовое представление.

---

## 20. Tone of voice

Тексты интерфейса:

- короткие;
- технически точные;
- без маркетингового пафоса;
- без лишних англицизмов, если есть нормальный русский эквивалент.

Примеры:

```text
Анализировать
Добавить в загрузки
Приостановить
Повторить
Открыть папку
Проверить снова
```
