# REQ-056 — [AUTH] Оформление приватной страницы Device Authorization

## Requirement

Временная локальная browser-страница Device Authorization оформляется по `docs/brand/mockups/10-auth.png` с готовой иконкой `docs/brand/icon.png` и визуальными токенами `docs/brand/brandbook.md`. Страница показывает актуальный user code, позволяет скопировать его, открыть проверенный официальный verification URL и отменить текущую авторизацию. Оставшееся время и полоска срока действия рассчитываются по фактическому deadline challenge, без продления его жизни ради интерфейса.

Страница сохраняет приватный provider-owned lifecycle по ADR-010, работает с локальными ресурсами из собранного provider package и остаётся доступной при изменении ширины окна и управлении с клавиатуры. Новые визуальные элементы не меняют OAuth polling, проверку аккаунта, хранение credentials и публичные контракты авторизации.

## Rationale

Пользователь предоставил макет и иконку для оформления уже существующей страницы `auth-browser.ts`. Отдельное требование фиксирует пользовательские действия и визуальное качество этой страницы; REQ-048 продолжает описывать будущий React + MUI desktop UI.

## Acceptance

- Страница сверена с макетом при viewport 1448 × 1086: шапка, вступление, карточка кода слева, инструкция справа и footer; screenshot evidence содержит обоснование видимых отличий. При viewport 640 × 900 основные блоки располагаются в одну колонку без горизонтальной прокрутки и обрезанных действий.
- Готовая PNG-иконка используется в шапке и favicon с сохранением пропорций; основные CTA используют primary брендбука, а не жёлтый цвет иконки.
- Актуальный код копируется с понятным подтверждением; отказ clipboard сопровождается сообщением и возможностью выделить код вручную. Переход ведёт на фактический проверенный HTTPS verification URL, hostname которого показан на странице.
- Таймер и полоска отражают реальный оставшийся срок challenge и не сбрасывают deadline при открытии или перезагрузке страницы. Отмена прекращает текущий flow существующим механизмом; разрыв связи не объявляется успешной авторизацией.
- Собранный provider package содержит необходимые локальные ресурсы: страница и favicon работают вне корня репозитория, без обращения к исходному `docs`, CDN, внешним шрифтам или аналитике.
- Все действия доступны с клавиатуры и видимым focus; статусы и ошибки имеют текстовое представление. Авторизация не запрашивает пароль пользователя.
- Сохраняются loopback bind, непредсказуемый путь, no-store, no-referrer и корректное экранирование динамических данных. Access/refresh/device token, cookies, Authorization, user code и приватный URL не попадают в logs/CLI output/DTO/events; исключение для краткоживущего user code остаётся только в приватной странице. Success/error/timeout/cancel освобождают ресурсы по ADR-010.
