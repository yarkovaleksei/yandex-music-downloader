# REQ-041 — [TOOLING] Локальные проверки перед слиянием

## Requirement

Перед слиянием изменения проверяются локально: lint, typecheck, unit tests, integration tests, build CLI и build core. Сборка CLI/core/desktop и подготовка всех платформенных артефактов выполняются только на Linux. Desktop дополнительно проверяется Electron E2E; на Windows/macOS запускаются готовые собранные на Linux артефакты без компиляции приложения или тестового host. По уточнённому решению владельца от 2026-10-29 CI приложения выполняет только дополнительные Linux-проверки кода и unit tests; успешный CI не является условием завершения STEP или релиза.

Решением владельца от 2026-10-29 все новые нативные проверки Windows/macOS выполняются единым финальным STEP-054 после разработки, упаковки и механизмов подписания/обновления. Отсутствие этих прогонов не блокирует промежуточные STEP; там обязательны Linux-проверки. Перед выпуском финальная Windows/macOS приёмка обязательна. Все сборки выполняются только на Linux; на целевых ОС проверяются готовые артефакты. При добавлении новой работы финальный STEP-054 должен зависеть от её завершения.

Исключение по решению владельца от 2026-10-29: STEP-058 реализует переносимые UI-функции и соответствие макетам и не является prerequisite STEP-054. STEP-054 может завершиться независимо от STEP-058; его нативные отчёты относятся к проверенным revision/build ID, а не автоматически к будущей UI-сборке. Повторные Windows/macOS прогоны не требуются для завершения STEP-058; новые платформенные интеграции в его scope запрещены.

## Rationale

Регрессии должны ловиться до слияния (brief §42).

## Acceptance

- Перечисленные локальные команды завершаются успешно; Evidence содержит revision, команды и результаты.
- Обязательные проверки не используют `PROVIDER_TEST_TOKEN` и не выполняют `test:provider`.
- Harness validation выполняется локально. CI приложения выполняет дополнительные проверки только на Linux; Windows/macOS, Electron E2E и сборки дистрибутивов в нём не запускаются. Workflows CI Harness сохраняются без изменений. Ожидание или отказ CI не блокирует приёмку STEP.
