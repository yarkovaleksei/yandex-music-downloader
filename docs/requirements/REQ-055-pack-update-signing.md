# REQ-055 — [PACKAGING] Проверенные обновления portable-приложения

## Requirement

По запросу пользователя приложение проверяет доступную версию, скачивает portable-пакет и проверяет его подлинность собственной Ed25519-подписью описания релиза, версией, целевой ОС/архитектурой, размером и SHA-256. После проверки пользователь открывает папку с пакетом и заменяет приложение вручную. Фоновое скачивание, автоматическая установка и запуск неподтверждённого пакета отсутствуют. Платные сертификаты, системная code signing и Apple notarization не требуются по решению владельца от 2026-10-29. Приватные ключи не хранятся в репозитории или пакете.

По решению владельца от 2026-10-29 нативные проверки Windows/macOS выполняются на готовых артефактах после разработки и упаковки; промежуточные изменения проверяются на Linux. Перед выпуском обязательна финальная приёмка Windows/macOS. Все сборки выполняются только на Linux; на целевых ОС проверяются готовые артефакты без компиляции.

Отчёты нативной приёмки относятся к конкретным revision/build ID и хешам. Для ранее согласованных переносимых изменений UI без новых платформенных интеграций разрешена отдельная Linux-проверка; прежний платформенный PASS не переносится автоматически на новую сборку.

Решение владельца от 2026-10-30: рабочий канал публикуется в GitHub Releases текущего репозитория `yarkovaleksei/yandex-music-downloader`, который становится публичным. Готовые portable-пакеты и подписанные описания доступны без GitHub-аккаунта/токена; production-адреса и открытый ключ включаются в сборку. Приватный ключ остаётся в системном защищённом хранилище Linux-сборщика. Первую сборку с настроенным каналом пользователь устанавливает вручную.

Рабочий канал подключён после исторической платформенной приёмки. Новые отчёты о канале связываются с фактическими версиями и хешами; прежние платформенные PASS не подтверждают новые сборки. Готовность конкретного релиза требует применимых проверок.

## Rationale

Решение владельца от 2026-10-29 и разрешённый OQ-013 заменяют требование платной подписи. ADR-019 сохраняет криптографическую проверку обновлений без обещания доверия ОС к издателю.

## Acceptance

- Документированная схема обновления проверена обновлением с версии N на N+1: результаты Linux и Windows/macOS сохраняются с версиями и хешами проверенных пакетов.
- Локальная проверка на Linux подтверждает валидное обновление и отказ на неверную подпись, версию, цель, размер или хеш. Пакет не запускается автоматически; при отказе текущая версия, база и credentials сохраняются. Windows/macOS проверяются на готовых пакетах при платформенной приёмке.
- В репозитории отсутствуют приватные ключи: ключ собственной подписи хранится в защищённом хранилище ОС Linux-сборщика, в приложение включается только открытый ключ. Скачивание допускает HTTPS и настроенные доверенные origins; доверие ключу из сети запрещено.

- Приёмка рабочего канала подтверждает реальный анонимный путь от публичного релиза до Linux N → N+1: проверка подписи, скачивание и проверка пакета, ручная замена, запуск с сохранением состояния/контрольного файла и отсутствие обновления при повторной проверке N+1. Для всех четырёх целей доступны соответствующие пакеты и подписанные описания; неполные и неподходящие релизы не предлагаются как готовое обновление.
