# REQ-010 — [QUALITY] Выбор качества по фактически доступным вариантам

## Requirement

Core запрашивает у provider доступные `AudioVariant`, отфильтровывает неподдерживаемые, сопоставляет пользовательскую настройку (`best`, `lossless`, `high`, `normal`) и выбирает лучший подходящий вариант; фактически выбранный variant сохраняется в job и manifest. Жёсткая связь «Premium = FLAC» или «High = 320 kbps» не допускается. Если выбранная настройка (`lossless`, `high`, `normal`) недоступна для трека, трек получает `QualityUnavailableError` без тихого снижения качества, а остальные треки job продолжаются; `best` выбирает лучший из доступных вариантов: lossless предпочтительнее lossy, среди lossy — больший bitrate, при равенстве — первый по порядку provider. Если после фильтрации неподдерживаемых вариантов не осталось ни одного, трек получает `QualityUnavailableError`. Правила ранжирования, определяющие `high` и `normal`, фиксируются по evidence (OQ-011).

Уточнение (решение владельца продукта, 2026-10-10, OQ-011): `high` — максимальный, `normal` — минимальный bitrate среди поддерживаемых lossy-вариантов одного codec (при одном варианте оба пресета выбирают его); bitrate разных codec не сравнивается — группу выбирает внедряемое ранжирование codec, а без него берётся codec первого подходящего lossy-варианта в порядке provider. Это же правило группы действует в lossy-ветке `best`.

Уточнение UI по REQ-058: пользователь может явно выбрать подтверждённые provider codec/bitrate как отдельный режим выбора варианта. Это не меняет ранжирование и смысл прежних предпочтений `best/lossless/high/normal`, не разрешает транскодирование или тихое снижение качества и не связывает подписку с форматом. Недоступные варианты не обещаются.

## Rationale

Состав вариантов зависит от аккаунта и трека, а не от предположений.

## Acceptance

- Для набора вариантов и настройки `best` resolver возвращает вариант с максимальным рангом, а для `lossless` — лучший lossless-вариант; пример входов/выходов покрыт unit-тестами.
- В job/manifest каждого трека записан фактически выбранный variant (codec, bitrate, lossless, container).
- Для `lossless` при отсутствии lossless-варианта трек завершается `QualityUnavailableError`, остальные треки job продолжаются; снижение качества без явного указания не происходит.
- В коде отсутствуют константы, связывающие тип подписки или настройку качества с конкретным кодеком/битрейтом; правила `high`/`normal` соответствуют resolution OQ-011; preview-варианты никогда не выбираются (OQ-012).
