# REQ-002 — [AUTH] Безопасное хранение токена в CLI

## Requirement

Access/refresh token CLI хранится в защищённом локальном хранилище (механизм описан в ADR-010). Токен не хранится открытым текстом в `settings.json`, SQLite, logs и manifest; файловое хранилище, если используется, создаётся с правами доступа только для владельца.

## Rationale

Утечка токена даёт доступ к аккаунту пользователя.

## Acceptance

- После `auth` ни один из файлов settings/manifest/log не содержит значение токена (автоматическая проверка по сохранённому тестовому токену).
- Если используется файл, его права на POSIX — `0600`, на Windows — доступ только текущему пользователю; нарушение прав диагностируется командой `doctor`.
- Удаление авторизации (`logout` или эквивалент авторизации) удаляет токен из хранилища.
