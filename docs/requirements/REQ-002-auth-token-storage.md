# REQ-002 — [AUTH] Безопасное хранение токена в CLI

## Requirement

Access/refresh token CLI хранится в защищённом локальном хранилище (механизм фиксируется ADR по результатам STEP-005/STEP-006). Токен не хранится открытым текстом в `settings.json`, SQLite, logs и manifest; файловое хранилище, если используется, создаётся с правами доступа только для владельца.

## Rationale

Утечка токена даёт доступ к аккаунту пользователя (brief §10).

## Acceptance

- После `auth` ни один из файлов settings/manifest/log не содержит значение токена (автоматическая проверка по сохранённому тестовому токену).
- Если используется файл, его права на POSIX — `0600`, на Windows — доступ только текущему пользователю; нарушение прав диагностируется командой `doctor`.
- Удаление авторизации (`logout` или эквивалент, определяемый STEP-008) удаляет токен из хранилища.
