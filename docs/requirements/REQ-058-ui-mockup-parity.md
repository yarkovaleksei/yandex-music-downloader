# REQ-058 — Функциональная полнота desktop UI и соответствие макетам

## Requirement

Решением владельца от 2026-10-29 недостающие функции макетов `docs/brand/mockups/01..10` становятся явным продуктовым контрактом. Макеты определяют компоновку, визуальную иерархию и доступность действий; примерные музыкальные данные и значения подписки не являются данными настоящего пользователя. Сохраняются принятые улучшения REQ-057: закреплённая навигация, использование ширины окна, свёрнутые по умолчанию загрузки и компактные действия. Основной стек и правила оформления остаются по REQ-048.

- Главная содержит примеры поддерживаемых ссылок и очистку ввода. Предпросмотр показывает описание коллекции, общую длительность, автора с доступным изображением и миниатюры обложек; для отсутствующих данных используется честный fallback.
- Загрузки имеют вкладки «Очередь», «Активные», «Завершённые», «Ошибки» со счётчиками. Карточки показывают название, исполнителя или автора и доступную обложку вместо технического ID как основной подписи; доступные действия сгруппированы в меню. Прогресс и допустимые действия сохраняют REQ-050 и REQ-057.
- История сохраняет поиск и действия REQ-051, получает сортировку по столбцам, выбор произвольного периода календарём и дату со временем.
- Настройки разделены на «Основные», «Загрузка», «Файлы», «Внешний вид», «О программе». Добавлены сохраняемые настройки записи тегов, отдельного `cover.jpg`, создания `.m3u8` и темы. Новые задания и повторная загрузка используют снимок выбранных параметров; действующие задания не меняются задним числом. Для прежних сохранённых настроек отсутствие новых полей сохраняет текущее поведение: теги, встроенная обложка, `cover.jpg` и `.m3u8` включены, тема светлая. Переключатель тегов управляет текстовыми метаданными, отдельная обложка не подменяет встроенную; REQ-026 сохраняет их независимость.
- Диалог качества имеет черновой выбор, «Применить» и «Отмена». Помимо прежних предпочтений REQ-010 допускается явный выбор codec/bitrate только из подтверждённых provider вариантов с покрытием коллекции. MP3 320/256/128, AAC 256 и FLAC из макета не обещаются без соответствующего варианта. Нет перекодирования, тихого снижения качества или изменения смысла `best/lossless/high/normal`; значение по умолчанию не меняется только из-за подписи на картинке.
- Аккаунт показывает email, регион, сведения о подписке и доступных форматах только при наличии подтверждённых данных provider; иначе у поля явно указано отсутствие данных. Нельзя выводить доступность FLAC только из названия подписки. Yandex-специфичная проекция принадлежит provider, renderer получает безопасный DTO.
- Уведомления об успехе и ошибке соответствуют макету 09 и различают полный успех, частичную ошибку и отмену. Представление обновлений следует макету, но процесс остаётся ручным portable-обновлением ADR-019; настройка production feed и системная установка в это требование не входят. Функции авторизации макета 10 сохраняются без переделки auth flow.

## Rationale

Владелец запросил реализацию функций, отсутствующих при сравнении десяти макетов с текущим desktop UI. Это дополнение ранее принятого desktop UI. По решению владельца переносимые изменения интерфейса без новых платформенных интеграций проверяются отдельно на Linux. Нативные отчёты сохраняют привязку к проверенным артефактам и не подтверждают будущую UI-сборку.

## Acceptance

- Для каждого макета 01–10 сохранён checklist «реализовано / согласованное отличие» и актуальный screenshot на синтетических данных; перечисленные функции реализованы, отличия REQ-057 явно отмечены.
- Фильтры загрузок и их счётчики, сортировка и диапазон дат истории работают на смешанном наборе состояний; прежние управление заданиями, ссылки, replay и скрытие без удаления файлов сохранены.
- Настройки восстанавливаются после restart; включение и отключение тегов, `cover.jpg` и `.m3u8` меняют фактический результат загрузки; старая конфигурация сохраняет прежние defaults, а replay сохраняет эффективные параметры задания. По решению владельца от 2026-10-29 автоматическое открытие папок и соответствующая настройка удалены, включая поведение ранее созданных заданий. Папка открывается только явным действием пользователя.
- «Отмена» или закрытие диалога не изменяет качество; «Применить» сохраняет выбранный доступный вариант. Проверены частичное покрытие, отсутствие варианта и сохранение прежних preference-правил.
- Отсутствующие account/preview данные не выдумываются и не ломают экран; токены, credentials и signed URL не попадают в DTO, screenshots или Evidence.
- Локальные Linux unit/integration и Electron E2E проходят; переносимые изменения UI без новых платформенных интеграций не требуют новых Windows/macOS отчётов. Прежние отчёты сохраняют результаты только для проверенных артефактов.
