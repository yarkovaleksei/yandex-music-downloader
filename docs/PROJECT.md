# Project

> Нормализованное описание проекта. Источник: локальный brief (`PROJECT_BRIEF.local.md`, не коммитится) и принятые при `PROJECT INIT` REQ/ADR/OQ.

## Название

Yandex Music Downloader (`yandex-music-downloader`) — кроссплатформенный загрузчик Яндекс Музыки.

## Краткое описание

Кроссплатформенное приложение для Linux, macOS и Windows, позволяющее авторизованному пользователю сохранять локально доступные ему материалы Яндекс Музыки: треки, альбомы и плейлисты — с выбором доступного качества, тегами, обложками, структурой каталогов, `.m3u8` для плейлистов, очередью, повторными попытками, восстановлением после прерывания и историей загрузок.

Проект развивается в два этапа:

1. **Headless Downloader Core + CLI** (`music-downloader`) — проверка жизнеспособности идеи без графического интерфейса.
2. **Desktop UI** (Electron + React + TypeScript + MUI + Vite) — клиент существующего core; начинается только после выполнения критерия перехода (REQ tool-headless-gate, STEP-027).

## Проблема и цель

Пользователю нужен надёжный способ локально сохранять доступный его аккаунту контент с корректными метаданными и структурой файлов. Используемый API Яндекс Музыки неофициальный и потенциально нестабильный, поэтому ключевая цель архитектуры — полная изоляция Yandex-специфичного кода от downloader core и клиентов, диагностируемость дрейфа API и отсутствие повреждённых файлов при сбоях.

## Пользователи / участники

- Авторизованный пользователь Яндекс Музыки, которому нужна локальная копия доступного ему контента (CLI в этапе 1, desktop в этапе 2).
- Разработчики/автоматизация, использующие `--json` режим CLI для тестов и интеграции.
- Владелец проекта, принимающий решения по открытым вопросам (OQ) и переходу к UI.

## Ключевые сценарии

- Авторизация без передачи пароля, определение текущего аккаунта, обработка истёкшего токена.
- Загрузка трека, альбома или плейлиста по ссылке с выбором качества из фактически доступных вариантов.
- Запись тегов и обложек, структура каталогов, `.m3u8` для плейлистов.
- Очередь с параллелизмом, pause/resume/cancel/retry, восстановление после перезапуска, пропуск уже скачанного.
- Диагностика (`doctor`), структурированные логи, различение сетевых ошибок и изменения API.
- (Этап 2) Предпросмотр по ссылке, экраны Downloads/History/Settings/Account/Diagnostics, уведомления, дистрибутивы для трёх ОС.

## Границы продукта

### In scope

- Provider layer для Яндекс Музыки с runtime-валидацией ответов и версией совместимости.
- Headless downloader core, application API и CLI.
- Метаданные, обложки, `.m3u8`, валидация файлов, кэш с TTL, doctor, структурированное логирование.
- После gate: SQLite persistence с миграциями, Electron + React + MUI UI, упаковка, подписание и автообновление.
- Платформы: Windows x64, macOS arm64, macOS x64, Linux x64.

### Out of scope

- Другие сервисы: Spotify, Apple Music, VK Music, YouTube Music (архитектура не должна блокировать их добавление).
- Browser extension, мобильное приложение, облачная синхронизация, multi-user и server mode, web-приложение.
- Автоматическая библиотека транскодирования, рекомендации, плеер, менеджер библиотеки.
- Расшифровка offline-cache официального клиента, извлечение ключей, MITM, модификация клиента, обход DRM и ограничений аккаунта, чужие credentials.

## Ограничения

- Только варианты аудио, которые provider сообщает доступными текущему аккаунту (PRN-003).
- Пароль пользователя Яндекса не запрашивается и не хранится; токен не хранится и не логируется в открытом виде (PRN-002).
- Yandex-специфичный код и `@dvxch/yandex-music` — только в `packages/providers/yandex-music` (PRN-001, ADR-001, ADR-002).
- TypeScript `strict`, Node.js 20+; запрет необоснованного `any`.
- React UI не начинается до стабильного headless core.
- Бренд: собственная визуальная идентичность без использования брендинга Яндекса (`docs/brand/brandbook.md`).

## Нефункциональные ожидания

- Надёжность: запись через `.part` и атомарный rename, восстановление после прерывания, retry только для transient-ошибок.
- Диагностируемость: structured logging, события с `jobId`/`trackId`/`durationMs`, нормализованные доменные ошибки, provider health.
- Безопасность: редакция секретов, безопасная модель Electron (contextIsolation, sandbox, typed IPC).
- Тестируемость: core проверяется на mock provider; live-тесты API — отдельный suite.
- Переносимость: единый кроссплатформенный filename sanitizer.

## Основные риски и неопределённости

См. `docs/OPEN_QUESTIONS.md`. Ключевые риски: нестабильность неофициального API (дрейф схемы, лимиты, TTL signed URL), неизвестный стабильный auth flow, состав кодеков/контейнеров, кроссплатформенность атомарной записи, выбор библиотеки тегов и secure storage.
