# ADR-019 — Portable-дистрибутивы и проверенные обновления без платных сертификатов

## Context

Владелец 2026-10-29 отказался от покупки сертификатов вообще, а не только на время разработки. Требуются portable-версии. STEP-035 уже создал локальные unsigned AppImage/NSIS/.app ZIP; его исторические результаты сохраняются. Все сборки выполняются на Linux, вся новая нативная приёмка Windows/macOS остаётся последним STEP-054.

## Problem

ADR-018 требует системной подписи и notarization, а выбранный в нём macOS updater зависит от подписанного приложения. Нельзя сохранять эти требования как блокирующие или выдавать собственную подпись пакета за доверие Apple/Microsoft к издателю. Нужна проверка обновлений для portable-пакетов без системного установщика.

## Decision

Это решение заменяет ADR-018 для будущей реализации и релизов. Linux-only сборщик electron-builder 26.18.1, production closure, target-native bindings, стабильные app/bundle ID, shipping fuses и ASAR integrity сохраняются. Новые форматы: Windows x64 ZIP с готовым приложением, macOS arm64/x64 .app ZIP, Linux x64 AppImage. NSIS не является требуемым portable-артефактом; STEP-036 заменяет его ZIP. Portable означает запуск без установщика; расположение SQLite, аудио и credentials остаётся прежним по ADR-014/015, данные не переносятся рядом с executable.

Платная системная code signing, Developer ID, notarization/stapling, сертификаты Windows и инструменты rcodesign/osslsigncode не требуются. Предупреждения ОС о неизвестном издателе и повторная авторизация при отказе доступа к Keychain допустимы; отсутствие предупреждений и стабильный доступ к Keychain без запросов не обещаются. Отказ credential store не приводит к plaintext fallback.

Обновления выполняются по явному действию пользователя: проверить версию, скачать проверенный portable-пакет, открыть его папку. Пользователь закрывает приложение и заменяет portable-файлы вручную. Автоматическая замена/запуск приложения, установка при закрытии и фоновое скачивание отсутствуют. electron-updater/Squirrel и системный installer не используются: они не нужны для этого процесса и не дают обещать автоматическую установку unsigned macOS-приложения.

Main владеет проверкой и скачиванием; renderer получает только безопасный DTO состояния. Application host продолжает владеть заданиями, SQLite и credentials. Описание релиза содержит version/channel/target/HTTPS URL/size/SHA-256 окончательного пакета и проверяется detached Ed25519-подписью над точными байтами до доверия полям. В приложение встраиваются открытый ключ и доверенные origins. Приватный ключ владельца хранится в защищённом хранилище ОС Linux-сборщика; секреты не передаются в renderer, аргументах команд или logs. Локальные тесты используют временные отдельные ключи и не подменяют production trust.

Допускается только более новая версия текущего канала и целевой архитектуры, HTTPS и заданные origins, включая redirects. Фактические байты скачанного файла проверяются по размеру и SHA-256 того же неизменного проверенного descriptor; неполные/неверные файлы не выдаются как готовые. Неверная подпись, неизвестный ключ, несовпадение версии/цели/хеша и сетевой отказ завершаются безопасной ошибкой, без запуска пакета, изменения базы или credentials. Ключ из сети автоматически не принимается. Без настроенного production trust/feed функция явно недоступна, а не доверяет произвольному пакету.

Проверка Linux N → N+1 включает готовые локальные приложения двух явно проверочных версий, получение и проверку пакета N+1, ручную замену и запуск новой версии с сохранением общего состояния. Нет заявления о Git-теге или опубликованном релизе. Forward-only SQLite и запрет небезопасного downgrade/автоматического восстановления базы сохраняются по ADR-014.

## Alternatives considered

### Платные сертификаты и системное автообновление

Отклонено явным решением владельца. Требовало бы Apple Developer ID и Windows code signing, противоречит выбранному способу распространения.

### Непроверяемые ссылки на архивы

Проще, но не обеспечивает защиту от подмены пакета или feed. Отклонено: собственная криптографическая подпись не требует платного сертификата.

### Собственный автоматический заменяющий процесс для каждой ОС

Создаёт дополнительный платформенный installer и риски замены работающего executable/прав/восстановления. Не требуется для portable-распространения; выбран проверенный download и явная ручная замена.

## Consequences

Убраны расходы на сертификаты и обязательства notarization. Пользователь сам заменяет portable-пакет; доверие ОС к издателю и бесшовное системное автообновление отсутствуют. STEP-036 реализует ZIP Windows, проверку и скачивание обновления, собственную подпись release descriptor, Linux-доказательство N → N+1 и инструкцию. STEP-054 проверяет запуск portable Windows/macOS, offline E2E и тот же процесс обновления в конце проекта. Старые PASS/FAIL не переоцениваются.

## Security implications

Ed25519 подтверждает соответствие пакета ключу владельца, но не является Authenticode/Developer ID. Сохраняются PRN-001/002/003, ADR-015 fuses/CSP/IPC, защищённое хранение credentials и отказ без fallback. Подлинность feed и payload обязательна; проверка подписи не ослабляется из-за отсутствия платного сертификата. Ручная замена пакета не даёт приложению прав выполнять произвольные команды.

## Data / migration implications

Новых миграций нет. Общий stateDir сохраняется при замене portable-файлов. Обновление не переносит, не удаляет и не откатывает SQLite, аудио и credentials. Запуск старого клиента после forward-only миграции безопасно отклоняется согласно ADR-014.

## Compatibility / operational implications

Все сборки/пакеты готовятся на Linux. Windows/macOS получают готовые приложения без компиляции и установленных Node.js/FFmpeg. Native-проверки отложены до STEP-054; неизвестный macOS x64/Rosetta FAIL не считается исправленным решением об упаковке. Доступность production feed и собственный ключ настраиваются отдельно; без них проверка обновлений сообщает понятную недоступность.

Основания: [Electron autoUpdater: системная подпись обязательна для Squirrel.Mac](https://www.electronjs.org/docs/latest/api/auto-updater), [electron-builder v26: Windows ZIP](https://www.electron.build/v26/docs/win/), [Electron: ограничения Keychain без подписи](https://github.com/electron/electron/blob/main/docs/tutorial/code-signing.md). Это ограничения выбранных платформ, а не доказательство нативного запуска текущей сборки.
