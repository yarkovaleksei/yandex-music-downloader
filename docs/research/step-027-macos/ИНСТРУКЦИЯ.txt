Проверка Yandex Music Downloader на macOS

Нужны macOS 13.5 или новее (Apple Silicon или Intel), интернет, браузер,
аккаунт Яндекс Музыки и примерно 10 ГБ свободного места.
Node.js 24.21.0 для обеих архитектур уже внутри архива.
Устанавливать Node.js, Homebrew, Git, Python или Yarn заранее не нужно.
FFmpeg для этой проверки необязателен.

1. Распакуйте STEP-027-macos.zip в обычную папку на локальном диске,
   например Downloads. Не запускайте прямо внутри ZIP.
2. Откройте Terminal. Напечатайте bash и пробел, перетащите в окно файл
   START_MACOS.command из распакованной папки и нажмите Enter.
   Это одна команда; chmod и установленный Node.js не нужны.
   Также можно открыть START_MACOS.command двойным щелчком.
3. Вставьте по очереди свои ссылки на трек, альбом и плейлист либо
   коллекцию «Мне нравится», доступные вашему аккаунту. В альбоме и
   плейлисте нужны хотя бы два доступных трека; выбирайте маленькие
   коллекции и полные треки обычной длительности, лучше от минуты.
4. Если требуется авторизация, скрипт откроет штатный вход в браузере.
   При обращении macOS к Login Keychain разрешите доступ своему приложению.
   Пароль, OAuth-токен и содержимое Keychain никому отправлять не нужно.
5. Дождитесь итогового PASS или FAIL. Скрипт сам установит закреплённые
   зависимости, выполнит проверки/сборку и девять реальных загрузок:
   трек, альбом и плейлист по три раза с автоматической паузой и resume.
   Не нажимайте Ctrl+C вручную: нужные прерывания выполняет скрипт.
6. Отправьте только report.json, путь к которому напечатан в Terminal.
   Он лежит в подпапке music-downloader-check-XXXXXX рядом с этим файлом.
   Музыку, node_modules, Keychain и полный вывод Terminal отправлять не нужно.

Если запуск не дошёл до обычного report.json, отправьте START_REPORT.json
из корня распакованной папки. Он содержит безопасный код отказа launcher.
Если Terminal вообще не запускает файл, сохраните текст системного сообщения.
Если macOS блокирует запуск проверенного компонента, используйте штатное
«Открыть всё равно» в System Settings → Privacy & Security, когда оно доступно.
При запрете корпоративной политикой сообщите владельцу проверки.
Системные защитные настройки скрипт не отключает.

Runtime, зависимости, тестовые файлы, медиа и отчёты создаются внутри этой
папки. Авторизация и состояние заданий используют штатные хранилища текущего
пользователя. После отправки отчёта комплект и его аудиофайлы можно удалить.
Это не устанавливает Node.js в систему. Каждый запуск создаёт новый runtime
и новую папку проверки; старые результаты не выдаются за повторную загрузку.

Приёмка относится к исходникам
sha256:25a6a43bde2aa78ac3f5d74f533cec434ff0173d87859dbf0dfcaf78c0fdea07.
На этой версии Linux и Windows уже дали по 9/9 реальных циклов PASS.
Местная проверка launcher на Linux не заменяет реальную проверку macOS.
