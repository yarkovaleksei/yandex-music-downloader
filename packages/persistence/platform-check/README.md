# Платформенная проверка SQLite store

Набор проверяет, что `better-sqlite3` загружается и SQLite store работает на вашей платформе (ADR-014, ADR-017). Node.js уже внутри набора. Устанавливать Node.js, Yarn или что-то ещё не нужно, сеть не нужна.

## Что запускать

| Платформа                       | Архив                                             | Запуск                           |
| ------------------------------- | ------------------------------------------------- | -------------------------------- |
| Windows x64                     | `music-downloader-platform-check-windows-x64.zip` | двойной клик `run-windows.cmd`   |
| macOS (Apple Silicon или Intel) | `music-downloader-platform-check-macos.zip`       | двойной клик `run-macos.command` |

1. Скопируйте архив в локальный каталог, например на рабочий стол, и распакуйте его там. В виртуальной машине не распаковывайте набор в общую папку VirtualBox: база должна лежать на локальном диске.
2. Запустите файл из таблицы двойным кликом.
3. Дождитесь строки «Готово» и пришлите файлы `report-*.json` из каталога набора.

На Mac с Apple Silicon проверка выполняется дважды: arm64 нативно и x64 через Rosetta. Если Rosetta не установлена, x64 будет пропущена; установите её командой `softwareupdate --install-rosetta --agree-to-license` и запустите набор ещё раз. На Intel Mac выполняется только x64.

## Если система не даёт запустить

- **macOS, Gatekeeper.** Если появилось «не удаётся открыть, так как разработчик не подтверждён», откройте «Системные настройки → Конфиденциальность и безопасность» и нажмите «Открыть всё равно». Либо выполните в Терминале `xattr -dr com.apple.quarantine <каталог набора>` и запустите снова.
- **Windows, SmartScreen.** Нажмите «Подробнее → Выполнить в любом случае». Если файлы заблокированы как скачанные из интернета (Mark-of-the-Web), откройте свойства архива до распаковки, отметьте «Разблокировать» и распакуйте заново.

## Какие файлы прислать

- Windows x64: `report-win32-x64.json`.
- Mac с Apple Silicon: `report-darwin-arm64.json` и `report-darwin-x64-rosetta.json`.
- Intel Mac: `report-darwin-x64.json`.

Отчёт содержит только платформу, архитектуру, версии Node.js/SQLite/better-sqlite3, идентификатор загруженного prebuild, статусы проверок и сведения о сборке набора. Имени компьютера, имени пользователя и путей в отчёте нет.

## Для разработчика

- Сборка: `python3 packages/persistence/platform-check/build-kit.py [--copy-to <каталог>]`. Архивы и кэш загрузок Node.js 24.21.0 (с проверкой `SHASUMS256.txt`) лежат в `.cache/platform-check/`.
- Перед передачей каждый архив распаковывается во временный каталог вне репозитория, и `check.mjs` запускается локальным Node.js из распакованного дерева. Передавать можно только при PASS.
- Изменение `src` persistence/shared или `yarn.lock` после сборки требует пересборки набора и повторного прогона: `kitManifest` отчёта фиксирует build-id, git HEAD, чистоту дерева и sha256 dist и `yarn.lock`.
- Отчёты хранятся локально вместе с версией проверенного набора и хешами файлов; в исходники проекта они не добавляются.
