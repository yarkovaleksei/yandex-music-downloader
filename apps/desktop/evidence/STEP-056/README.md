## Исправление F-001: недоступные обложки

После воспроизведения сетевой блокировки локальной истории получение обложек вынесено в отдельный `historyArtwork({jobId})`. Чтение истории не ожидает provider/CDN; изображение дополняет уже показанную строку, ошибка оставляет fallback. Renderer не обращается к CDN напрямую.

В сценарии `scenario=cover-pending` два запроса обложек оставлены с неразрешающимися Promise. Все три локальные записи и действия видны (`history-pending-covers.png`); удаление старой записи доступно и сразу оставляет две строки (`history-pending-covers-hide.png`). Это наблюдение фиксирует прямое исправление F-001, а не измерение производительности. Regression-тесты application/renderer проверяют независимость строк от удержанного/отклонённого provider, безопасный отдельный DTO и поздние ответы.

## Воспроизведение и границы

`visual-fixture.txt` — исходник синтетического сценария. Для воспроизведения его нужно поместить как `visual.tsx` в `.harness/local/tmp/<execution>/`, собрать esbuild с JSX automatic, browser platform, alias `@music-downloader/shared=./packages/shared/src/index.ts` и file loaders для woff/woff2. `visual-index.txt` используется как index.html рядом с app.js/app.css; этот каталог раздаётся локальным HTTP-сервером. Параметры scenario=diagnostic-errors и os=win32/darwin выбирают соответствующие сценарии. По умолчанию показана Linux-помощь. Ссылки помощи ведут к фиксированным публичным страницам, включая [страницу загрузки FFmpeg](https://ffmpeg.org/download.html).

Эти снимки подтверждают визуальный результат. Сохранность очереди, migration/version guards, отсутствие запуска FFmpeg общим desktop collector, неизменность CLI doctor, частичные отказы и запрет повторов при неизвестном исходе доказываются тестами и generated Verification STEP-056. Синтетическая проверка не подтверждает реальный provider, системный keyring, Windows/macOS или CI. Незакоммиченная работа STEP-033 сохранена; её внешние CI/native gates остаются pending.
