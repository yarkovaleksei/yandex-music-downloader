### F-001 — Writer игнорирует отмену во время sync/close после EOF

**Severity:** medium
**Category:** implementation
**Location:** packages/core/filesystem/src/writer.ts:100
**Scenario:** Given Источник достиг EOF, writer выполняет завершающие sync/close с переданным AbortSignal. / When AbortController отменяет сигнал до завершения sync. / Then Writer возвращает успешный результат вместо AbortError.
**Expected:** Дескриптор закрыт, .part сохранён, операция завершается с AbortError согласно Implementation plan STEP-015.
**Observed:** После EOF сигнал не проверяется: при signal.aborted=true возвращается {bytesWritten:3}, cancelled=0, closed=1.
**Impact:** Вызывающий слой получает успех отменённой операции и может продолжить финализацию; нарушен явный контракт AbortSignal. Поведение будущей очереди не утверждается.
**Evidence kind:** reproduced
**Evidence source:** STEP-015 Implementation plan §2; writer.ts:100-106; независимый минимальный вызов public API.
**Verification method:** node --input-type=module: текущий public API, реальная временная ФС, injected sync отменяет сигнал перед реальным handle.sync.
**Verification result:** signalAborted=true; успешный {bytesWritten:3}; closed=1; cancelled=0; a.part сохранён с [1,2,3]; exit code 0.
**Fix direction:** Проверять отмену после EOF и завершающих файловых await до успешного возврата; сохранить cleanup и .part. Добавить один regression-тест abort во время sync.
**Fingerprint:** sha256:1b7e20f8f21344779995c4c231faefd4a1dfce7cec1d2932b844e68e1dbeb2c5

**Confirmed preconditions:**
- writeStreamToPart принимает AbortSignal.
- После EOF выполняются await sync и close.
- Сигнал отменён до завершения sync.

**Constraints:**
- Только существующий writer/API и его тесты в packages/core/filesystem.
- Не менять очередь, hooks, Range-resume, Accepted ADR и fingerprinted Ready plan.

**Evidence:**

- planning/tasks/STEP-015.md:133: при abort reader отменяется, дескриптор закрывается, .part остаётся, бросается AbortError.
