### F-001 — Отказ от новой WAL-схемы изменяет основной файл базы

**Severity:** medium
**Category:** implementation
**Location:** packages/persistence/src/sqlite-database.ts:118
**Scenario:** Given Более новая версия приложения оставила валидную SQLite-базу user_version=7 с подтверждёнными транзакциями в WAL после аварийного завершения процесса. / When Старый клиент вызывает SqliteManifestStore.list(): openStateDatabase создаёт writable-соединение до чтения user_version и закрывает его после обнаружения несовместимости. / Then STATE_SCHEMA_UNSUPPORTED возвращается, но закрытие соединения выполняет checkpoint; основной state.sqlite3 изменяется, WAL/SHM удаляются.
**Expected:** При отказе от новой схемы основной файл остаётся побайтно неизменным (STEP-029, Implementation plan §3; REQ-033).
**Observed:** Два независимых reviewers воспроизвели отказ с изменением файла. Lead: beforeLength=4096, afterLength=8192, mainUnchanged=false. Security: SHA-256 изменился с 97e8d54f8a7255106f66cf1b213c4a4d7b558d21310b1c2bfedc3d0d526dddda на 69d7a411d4761a42ff1a719c8062ce8a94426f78f3533985a5538968d8d4bc16; контрольный readonly inspect() сохранил байты и sidecars.
**Impact:** Старый клиент изменяет отвергнутую базу неподдерживаемого формата вопреки обязательной гарантии отказа без изменений. Потери логических данных эксперимент не показал.
**Evidence kind:** reproduced
**Evidence source:** Два независимых Node.js reproducer на текущем dist SqliteManifestStore и better-sqlite3 13.0.3.
**Verification method:** Создать future schema и WAL в дочернем процессе; завершить writer без закрытия, сравнить байты main file и sidecars до/после store.list(); отдельно проверить readonly inspect().
**Verification result:** list() отказывает с STATE_SCHEMA_UNSUPPORTED, но меняет main file и удаляет sidecars; readonly inspect() оставляет файлы неизменными.
**Fix direction:** Проверять совместимость существующей базы без writable-соединения, способного выполнить checkpoint при отказе. Сохранить проверку версии в транзакциях записи; добавить один regression-тест с непустым WAL новой схемы после аварии writer.
**Fingerprint:** sha256:05579c55c570bd2a623dbbd8a467f5548d4816ebf7ca7f7ee44bf6ba353495a8

**Confirmed preconditions:**
- Локальная WAL-база принадлежит текущему пользователю.
- user_version=7 превышает поддерживаемую версию 1.
- Writer завершился без db.close после committed WAL-транзакции, checkpoint ещё не выполнен.

**Admissible alternatives:**
- Другой механизм открытия/закрытия допустим, если подтверждает побайтную неизменность основного файла в воспроизведённом сценарии.

**Constraints:**
- Не пересоздавать, не мигрировать и не удалять базу будущей версии и её WAL/SHM.
- Сохранить безопасный публичный сигнал STATE_SCHEMA_UNSUPPORTED в application, CLI и doctor.
- Не ослаблять контроль user_version в транзакциях записи.
- Исправление ограничить packages/persistence и прямым regression-тестом внутри STEP-029.
