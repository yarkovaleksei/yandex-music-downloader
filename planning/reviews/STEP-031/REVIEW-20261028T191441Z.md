### F-001 — Штатная глобальная ошибка с паузой задания не вызывает уведомление

**Severity:** medium
**Category:** implementation
**Location:** apps/desktop/src/renderer/useDownloads.ts:98
**Scenario:** Given Задание загружается через существующий core; openAudioStream возвращает AuthenticationError, которую штатный retry policy преобразует в pause_job/AUTH_REQUIRED. / When Core сохраняет control=paused/pauseReason=AUTH_REQUIRED и заканчивает run без job.completed; renderer получает свежий paused snapshot через listJobs/getJob. / Then readJob показывает paused snapshot, но не устанавливает error notice, поскольку completionPending заполняется только job.completed. Main jobNotifications также сразу игнорирует все остальные события; системного уведомления нет.
**Expected:** По REQ-050 завершение и ошибки сопровождаются уведомлениями; глобальная ошибка, останавливающая загрузку, должна дать безопасное понятное уведомление в UI и предусмотренном main-only системном пути.
**Observed:** Уведомления обоих новых путей требуют job.completed. Фактический core публикует это событие только для completed/completed_with_errors/failed при live.intent=running; AUTH_REQUIRED переводит live.intent в paused и этого события не создаёт. Текущий paused snapshot с pauseReason не инициирует уведомление.
**Impact:** При обычной ошибке авторизации задание останавливается без обещанного уведомления; в фоне пользователь не узнаёт о необходимости вмешательства, а на Главной отсутствует error notice.
**Evidence kind:** reproduced
**Evidence source:** REQ-050 + cheapest falsification experiment на реальном core manager и фактических новых notification consumers
**Verification method:** Минимальный Vitest под temporaryDirectory: actual manager+fixture; actual jobNotifications; renderHook actual useDownloads с фактическим потоком событий и paused snapshot.
**Verification result:** 1 test PASS; core paused/AUTH_REQUIRED, job.completed отсутствует, show не вызывался, hook.notice undefined.
**Fix direction:** Обрабатывать подтверждённую ошибочную паузу по актуальным snapshots и существующим application results, включая reconciliation/list после createDownload/resume/retry. Обеспечить интерфейсное сообщение и предусмотренное main-only системное уведомление, безопасный текст и дедупликацию; пользовательская пауза и отмена не должны считаться ошибкой. Подтвердить минимальным regression test штатный pause_job путь без job.completed. Конкретная внутренняя реализация остаётся решением FIX.
**Fingerprint:** sha256:55ceb28fb8bda6b2fd218bcc42b49a993f12a03b6db2594ceff9b0fc8b98bd88

**Confirmed preconditions:**
- Проверено: AuthenticationError от openAudioStream проходит существующую decideRetry и создаёт глобальную paused/AUTH_REQUIRED.
- Проверено: фактический manager не публикует job.completed для этой паузы.
- Проверено: оба consumer не уведомляют даже когда getJob/listJobs возвращают актуальный paused snapshot.

**Admissible alternatives:**
