### F-001 — Terminal shutdown возвращает успех без release при одновременном pause

**Severity:** medium
**Category:** implementation
**Location:** packages/core/downloader/src/manager.ts:156
**Scenario:** Given Все треки completed, intent running, loop заблокирован внутри writePlaylist; shutdown вошёл в terminal-ветвь. / When До завершения writer приходит owner pause через manager.command или control inbox. / Then Intent становится paused, loop пропускает close; shutdown возвращается без release.
**Expected:** Успешный shutdown подтверждает освобождение lease независимо от одновременного pause.
**Observed:** Bounded experiment завершил running/shutdown/pause, control paused, releases=[]; повторный shutdown потребовался для release.
**Impact:** Shutdown заявляет успех с занятой lease и действующими таймерами; resume сталкивается с оставшимся владельцем.
**Evidence kind:** reproduced
**Evidence source:** Independent lead reviewer bounded lead-check.test.ts с gate writer и одновременным pause.
**Verification method:** Bounded comparison current manager и копии без terminal shutdown блока.
**Verification result:** Current FAIL releases=[]; old-block-free PASS releases once.
**Fix direction:** После bounded(live.loop) дождаться существующего close(jobId,live) перед return; добавить regression simultaneous pause, сохранив closePromise/errors/timeout.
**Fingerprint:** sha256:44118a43f70441a283cfb61c89c113f90ed9bb3a49e0ee2849445fbf88ed6c1f

**Confirmed preconditions:**
- Terminal aggregate виден до завершения writer.
- Pause синхронно меняет intent.
- Control inbox поддерживает owner pause по ADR-004.

**Constraints:**
