### F-001 — Resolver удаляет ведущий ноль из UUID плейлиста

**Severity:** medium
**Category:** implementation
**Location:** packages/providers/yandex-music/src/url/resolve-yandex-music-url.ts:88
**Scenario:** Given Поддерживаемая публичная ссылка https://music.yandex.ru/playlists/01234567-89ab-cdef-0123-456789abcdef содержит UUID формы 8-4-4-4-12 hex; первый ноль UUID является частью идентичности ресурса. / When Вызывается resolveYandexMusicUrl; UUID проходит uuidPattern и передаётся в mediaReference. / Then mediaReference применяет canonicalNumericId и возвращает id 1234567-89ab-cdef-0123-456789abcdef вместо исходного UUID в нижнем регистре.
**Expected:** MediaReference плейлиста содержит id 01234567-89ab-cdef-0123-456789abcdef; UUID нормализуется только по регистру hex, а ведущие нули удаляются исключительно из десятичных track/album/kind id.
**Observed:** Получен {provider:"yandex-music",kind:"playlist",id:"1234567-89ab-cdef-0123-456789abcdef"}. UUID потерял одну позицию в первой группе.
**Impact:** Resolver выдаёт неверный canonical id для поддерживаемого подмножества UUID ссылок и нарушает STEP-007/REQ-009. Будущий потребитель getPlaylist получает повреждённую идентичность; выполнение API запроса в этом review не заявляется.
**Evidence kind:** reproduced
**Evidence source:** Гипотеза о вызове numeric normalizer из UUID ветки проверена прямым запуском фактического resolver на поддерживаемой ссылке.
**Verification method:** node --input-type=module: esbuild.build({entryPoints:["packages/providers/yandex-music/src/url/resolve-yandex-music-url.ts"],bundle:true,write:false,format:"esm",platform:"node"}); импорт результата через data URL; прямой await resolveYandexMusicUrl для указанной поддерживаемой ссылки и контрольного UUID.
**Verification result:** Воспроизведён неверный MediaReference.id без сети и без изменения файлов реализации; обычный UUID с 0 перед hex-буквой остаётся целым.
**Fix direction:** Ограничить удаление ведущих нулей десятичными path id. Возвращать UUID playlist целиком в нижнем регистре и добавить один regression fixture с ведущим нулём перед десятичной цифрой; существующая нормализация numeric id должна сохраниться.
**Fingerprint:** sha256:a1ad89229e9cbfab2f15b73450e75a465c079ee22416a5fea639f81165098fdb

**Confirmed preconditions:**
- Hostname music.yandex.ru входит в фактический supportedHosts; путь /playlists/<UUID> поддерживается Implementation plan и regex resolver.
- UUID 01234567-89ab-cdef-0123-456789abcdef соответствует uuidPattern; первая группа начинается с 0, за которым идёт цифра, поэтому canonicalNumericId удаляет часть UUID.

**Admissible alternatives:**
- Канонизировать numeric id перед вызовом общего конструктора MediaReference, оставив конструктор без изменения id.
- Явно различить numeric и opaque id при построении MediaReference, сохраняя UUID и legacy owner+kind полностью.

**Constraints:**
- Исправление остаётся внутри текущих resolver и его тестов STEP-007.
- Shared schema/API, сеть, auth, storage и новые зависимости для исправления не требуются.

**Evidence:**
- planning/tasks/STEP-007.md, Implementation plan §1: UUID playlist id — lowercase UUID формы 8-4-4-4-12 hex; numeric leading-zero normalization предусмотрена для track/album/kind.
- packages/providers/yandex-music/src/url/resolve-yandex-music-url.ts:68-70 передаёт UUID в mediaReference; строка 88 применяет canonicalNumericId к любому id; строки 91-92 удаляют начальные нули перед цифрой.
- Прямой вызов фактического resolver, скомпилированного esbuild в памяти: input UUID 01234567-89ab-cdef-0123-456789abcdef → actual.id 1234567-89ab-cdef-0123-456789abcdef, identityPreserved=false; exit code 0.
- Контрольный прямой вызов UUID 0abcdef0-1234-5678-9abc-def012345678 сохраняет identityPreserved=true и локализует эффект в numeric leading-zero helper.
- node packages/testing/scripts/run-yarn.mjs exec vitest run packages/providers/yandex-music/src/url/resolve-yandex-music-url.test.ts: exit code 0, 26/26 PASS; имеющийся UUID fixture начинается с 1 и не обнаруживает этот сценарий.
