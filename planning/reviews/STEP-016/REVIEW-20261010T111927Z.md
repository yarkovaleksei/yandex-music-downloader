### F-001 — Windows process identity probe прерывает acquire/recovery текущего живого процесса

**Severity:** high
**Category:** implementation
**Location:** packages/persistence/src/process-identity.ts:40
**Scenario:** Given Обычный Windows-2025 CI job PR11 исполняет production FileManifestStore/recovery с default currentLeaseIdentity на Node.js22.13.0 или24. / When Windows branch запрашивает StartTime текущего PID через powershell.exe, после чего acquire должен начать recovery. / Then processStartedAt возвращает undefined, а currentLeaseIdentity выбрасывает «Не удалось определить время старта текущего процесса»; real playlist restart и rename-gap tests не доходят до recovery.
**Expected:** Поддерживаемый Windows runtime должен получать birth текущего живого процесса и выполнять production acquire/recovery; bounded probe failure должен отличаться от отсутствующего PID.
**Observed:** Оба Windows CI logs содержат этот production отказ в application recovery suites; Node24 дополнительно имеет отказ в persistence owner-token test. В Windows execFile установлен timeout1000ms, а catch скрывает исходный error. Логи не сохраняют underlying execFile status, поэтому конкретный Windows startup timeout не объявляется измеренной root cause.
**Impact:** Production manifest/recovery недоступен в подтверждённых Windows запусках, а критический restart/checkpoint acceptance не исполняется.
**Evidence kind:** reproduced
**Evidence source:** Captured PR11 Windows jobs, production currentLeaseIdentity failure.
**Verification method:** Сверка обоих captured CI logs с actual processStartedAt/currentLeaseIdentity и production caller stack.
**Verification result:** Windows Node24:5 failed/848passed; Windows Node22.13:4failed/849passed. Оба содержат birth-query отказ в playlist и processing rename-gap suites.
**Fix direction:** Исправить Windows birth-query path: обеспечить достаточный bounded бюджет запуска PowerShell и безопасно различать успешный ответ, отсутствующий PID и неизвестный/timeout probe outcome. Сохранить numeric-PID query без command line/env secrets; подтвердить current/child/recovery в существующей Windows matrix.
**Fingerprint:** sha256:534668e4457d1ef282b49bb4544b9229c5f382b99c0e1747ce4e8bae7c70644f

**Confirmed preconditions:**
- Windows-2025 и обе поддерживаемые Node versions реально запускали production exported store/recovery tests.
- Current PID жив во время query; failure поднят текущим исполняющим процессом.

**Admissible alternatives:**
- Узко изменить бюджет/запуск текущего shell:false PowerShell adapter после проверки safe failure category; новая архитектура process identity не нужна.

**Constraints:**
- Исправление ограничено подтверждённым CI/runtime path STEP-016; не менять Accepted ADR/REQ.
- Не добавлять SQLite/CLI/UI/queue/Yandex или unrelated hardening; не пропускать обязательные Windows acceptance tests.
- Не подменять неизвестный probe отсутствием живого PID; независимый security finding по этой границе агрегирует root.
- Не утверждать точную длительность/причину PowerShell failure без captured error/timing.

### F-003 — Fixture mode конфликтует с Vitest MODE и не удерживает живую Windows lease

**Severity:** high
**Category:** implementation
**Location:** packages/persistence/src/file-manifest-store.integration.test.ts:81
**Scenario:** Given Vitest worker environment содержит MODE='test'; fork helper передаёт {...process.env,mode:'hold'}. Windows env keys сравниваются без учёта регистра, а Node выбирает первый лексикографически. / When Fixture получает winner MODE='test' вместо role mode='hold'; тот же pattern используется для application modes 'first' и 'rename-gap'. / Then Persistence child сообщает acquired, не входит в waitForRelease и сразу release/exit; следующий contender законно получает acquired. Application fixture также не выполняет first/rename-gap crash barriers при mode='test'.
**Expected:** Передаваемый fixture role должен однозначно доходить до child; hold child остаётся owner до release barrier, first/rename-gap helpers исполняют соответствующие crash barriers.
**Observed:** Оба Windows logs показывают live contender acquired вместо rejected. Существующий Vitest configResolved переносит viteConfig.env в process.env. Дешёвый falsification с официальным Windows env selection и реальным production fixture дал winningMode=test, ownerReported=acquired, ownerExitedBeforeContender=true, contender=acquired; отрицательный контроль без MODE collision дал contender=rejected.
**Impact:** Windows multiprocess proof проверяет уже освобождённую lease вместо живой; application crash/recovery proofs теряют свои barriers. Эти результаты не доказывают дефект native lock.
**Evidence kind:** reproduced
**Evidence source:** PR11 Windows live-contender failure и .harness/local/ci-step016-env-falsification.mjs.
**Verification method:** node .harness/local/ci-step016-env-falsification.mjs: Windows env selection emulation + unchanged production fixture/default native lock/real temporary filesystem, с отрицательным контролем.
**Verification result:** Exit0: winningMode=test; collisionOwnerReported=acquired; collisionOwnerExitedBeforeContender=true; collisionContender=acquired; controlOwner=acquired; controlContender=rejected. Все child processes завершены, временная ФС удалена.
**Fix direction:** Переименовать role env key в уникальный namespaced uppercase ключ и согласованно обновить оба fork helpers и оба fixtures в persistence/application. Сохранить реальные native lock и IPC barriers; не ослаблять acquired/rejected assertions.
**Fingerprint:** sha256:9ec7bed32c3acdcea2855480438183394978a2818932d1b1c822cd905ace5cf9

**Confirmed preconditions:**
- Project uses Vitest3.2.7; installed configResolved projects MODE to process.env.
- Actual fork env включает inherited MODE и lowercase mode; fixtures читают mode и выбирают роль по exact literals.
- Node Windows case-insensitive lexicographic env selection подтверждён official child_process docs.

**Admissible alternatives:**
- Сделать env transmission роли однозначным при Windows case folding без общей нормализации всех environment variables; использовать один явно проверяемый fixture key.

**Constraints:**
- Исправление ограничено подтверждённым CI/runtime path STEP-016; не менять Accepted ADR/REQ.
- Не добавлять SQLite/CLI/UI/queue/Yandex или unrelated hardening; не пропускать обязательные Windows acceptance tests.
- Исправление охватывает packages/persistence/src/fixtures/manifest-owner.mjs и packages/application/src/fixtures/recovery-owner.mjs плюс их fork callers.
- Не менять native lock на основании данного false concurrency failure.
- Не заменять реальные child-process proof mocks или skip Windows.

### F-004 — Неизвестный результат process probe ошибочно разрешает захват устаревшей аренды

**Severity:** medium
**Category:** implementation
**Location:** packages/persistence/src/process-identity.ts:70
**Scenario:** Given Same-host lease не освобождена, heartbeat просрочен, kernel lock свободен. PID из lease жив, но Windows birth probe завершается timeout/unavailable error и не может подтвердить identity. / When FileManifestStore.acquire проверяет retained lease через assertReclaimable → probeLease → processStartedAt. / Then processStartedAt возвращает undefined, probeLease объявляет missing, assertReclaimable принимает это за подтверждённое отсутствие процесса и выдаёт новую owner session, перезаписывая generation lease.
**Expected:** ADR-004 допускает stale reclaim только при подтверждённом отсутствии прежнего PID+birth либо другом birth. STEP-016 plan §3 отдельно требует отличать missing process от unavailable/permission/parse failure; unknown probe запрещает automatic reclaim.
**Observed:** Production Windows branch с injected ETIMEDOUT вернула undefined; реальный живой PID классифицирован как missing. При наличии unreleased same-host record с expired heartbeat и свободного настоящего native lock FileManifestStore.acquire успешно выдал session и заменил generation 41 на 42. В CI Windows Node 22.13.0/24 независимо зафиксированы повторные ошибки определения birth текущего процесса при запуске recovery.
**Impact:** Неизвестная identity превращается в положительное разрешение automatic reclaim: запускается recovery и меняется защищённый lease/owner state без обязательного доказательства отсутствия старого владельца. Kernel lock остаётся дополнительной границей; наличие двух реально живых writers этим finding не утверждается.
**Evidence kind:** reproduced
**Evidence source:** Current HEAD 33652d4b278f5d1899c00149271c8727f11c3c13; реальные Windows CI birth failures и минимальный fault injection через production processStartedAt/probeLease/FileManifestStore.acquire; ADR-004 и STEP-016 stale contract.
**Verification method:** Узкая fault injection Windows probe на Linux и реальная ФС/native lock; чтение lease до/после public acquire плюс проверка liveness PID. CI logs проверены отдельно.
**Verification result:** Живой PID + неизвестный birth → missing; acquire разрешён, lease generation изменена 41→42; exit 0. Строгий unknown refusal не выполнен.
**Fix direction:** Сохранить различие между недоступной birth probe и подтверждённо отсутствующим процессом при lease decision; unavailable/timeout/error у живого или неопределённого PID должен давать unknown и безопасный отказ. Настроить ограниченный Windows probe budget по реальному CI вместо текущего 1000 ms, сохранив bounded execution. Добавить узкую проверку timeout/alive → unknown с отсутствием изменения lease и подтверждённого missing → допустимый stale reclaim, затем подтвердить recovery на реальной Windows matrix.
**Fingerprint:** sha256:dbdfaba0ee04e5f553df80edbae24e8759d7458442b2a5e9af9bf07cc3bbdfeb

**Confirmed preconditions:**
- Lease same-host, unreleased и heartbeat истёк: записан record поколения 41 без releasedAt с heartbeat 2000-01-01.
- PID жив: process.kill(process.pid,0) успешен.
- Birth недоступен из-за execFile timeout: ETIMEDOUT injected в реальную Windows branch, timeout option 1000 captured.
- Native lock свободен: настоящий NativeJobLock successfully acquired; mock native locking не использовался.
- Эффект достигается через public acquire: выдана реальная session, прочитанное generation lease повышено до 42.

**Admissible alternatives:**
- Можно сохранить публичный processStartedAt: string|undefined. Если birth отсутствует, probeLease может выполнить process.kill(pid,0) только для разграничения alive → unknown, ESRCH → missing, остальные ошибки → unknown; этот fallback не должен подтверждать совпадение birth или заменять обычный PID+birth check.

**Constraints:**
- Не перепроектировать ManifestStore/ProcessIdentity API и не менять native lock по данным этого finding.
- Сохранить Windows/macOS bounded command execution и отсутствие raw command/environment/credentials в диагностике.
- Свободный kernel lock — обязательная проверенная предпосылка effect; при удерживаемом lock эта ветка acquire не достигается.
- Не связывать это finding с CI acquired/rejected assertion: там отдельно установлен конфликт MODE/mode в fixture lifetime.

**Evidence:**
- packages/persistence/src/process-identity.ts:35-46 запускает Windows PowerShell с timeout:1000; :48-51 возвращает undefined после любого caught failure; :69-70 переводит undefined в missing без проверки причины.
- packages/persistence/src/file-manifest-store.ts:65-82 сначала требует свободный native lock и затем проверяет prior lease; :160-166 отказывает только same/unknown, разрешая missing; :86-101 выполняет recovery и публикует новую generation.
- planning/tasks/STEP-016.md:161,163 прямо требуют confirmed absence/different birth и fail-closed unknown; docs/adr/ADR-004-atomic-finalization-and-manifest.md:53 задаёт тот же stale policy.

Логи не сохраняют исходный PowerShell error, поэтому конкретный timeout как причина этих CI сообщений не выдаётся за доказанный факт.

Проверены processStartedAt/probeLease для живого process.pid, затем реальный FileManifestStore.acquire с injected current identity, unreleased same-host lease, expired heartbeat и настоящим свободным native lock. Прочитан реальный lease.json: generation 41→42. Это Windows branch fault injection на Linux, не утверждение о локальном Windows runtime.
