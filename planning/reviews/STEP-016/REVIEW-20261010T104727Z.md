### F-002 — Release пропускает вложенную owner operation, принятую после начала закрытия

**Severity:** high
**Category:** implementation
**Location:** packages/persistence/src/file-manifest-store.ts:320
**Scenario:** Given Принятый runOwned callback ещё активен и остановлен Promise barrier. После вызова release он запускает новый вложенный runOwned и не ждёт его Promise; новая operation успешно регистрируется в activeOperations и тоже остановлена barrier. / When Первый callback завершается, а release дожидается только snapshot activeOperations из момента начала закрытия, помечает аренду released и освобождает lock. / Then Вторая session успешно acquire той же job и пишет .part через runOwned. Затем принятая вложенная operation первой session продолжается и перезаписывает .part нового владельца.
**Expected:** ADR-004 и STEP-016 plan §3 требуют прекращение приёма новых operations после начала release и отсутствие успешного release с незавершёнными принятыми side effects. Разрешение checkpoint уже принятому callback не должно разрешать старт нового artifact effect, не учитываемого release.
**Observed:** На реальном FileManifestStore после closing=true вложенный runOwned принят; release успешно завершился, пока его artifact callback оставался blocked; successor acquire и запись NEW! прошли; после снятия второго barrier old callback записал OLD! поверх файла нового owner. Literal output всех четырёх признаков — true.
**Impact:** Прямой регрессией FIX нарушается single-writer boundary: зарегистрированная операция старого owner остаётся активной после подтверждённой передачи аренды и портит partial текущей job. Исходный public finalization сценарий F-012 исправлен, но новая lifetime логика создаёт этот иной путь к тому же защищённому filesystem asset.
**Evidence kind:** reproduced
**Evidence source:** Прямой falsification check новой ALS/release логики из exact fix_delta patch; прежнее F-012 и обязательная owner/lifetime граница ADR-004/STEP-016.
**Verification method:** Deterministic Promise barriers, production FileManifestStore, две реальные session и writeFile/readFile; без mock native lock и временных sleep.
**Verification result:** Все четыре наблюдения true; exit 0. При обычном public finalization test исходная F-012 последовательность теперь безопасна, поэтому finding относится к новой lifetime regression.
**Fix direction:** Разделить разрешение checkpoint/save уже принятых effects и разрешение новых runOwned operations: после closing новый runOwned не должен приниматься только из-за унаследованного ownedContext. Release должен дождаться всех действительно принятых operations перед released/unlock. Добавить regression на точную воспроизведённую последовательность outer operation → release → nested runOwned → outer completion: либо nested operation отклоняется до callback, либо release не завершается до её окончания; successor не получает аренду с незавершённым old artifact effect.
**Fingerprint:** sha256:a2457c58b0d8d52867d6c066b2c22fab4295d04ffce257f83caec06f22e5e4eb

**Confirmed preconditions:**
- Новый ownedContext наследуется callback принятой runOwned operation; callback запускает nested runOwned после вызова release.
- При closing nested runOwned действительно принимается: callback начал исполняться и достиг второго barrier.
- Release действительно завершился до окончания nested effect: successor acquire той же job успешен.
- Старый accepted callback реально пишет в тот же .part после записи successor; итоговые bytes OLD! подтверждены чтением реальной ФС.

**Admissible alternatives:**
- Использовать явный lifetime admission/registration protocol, который охватывает разрешённых вложенных effects и закрывается только после их полного завершения; один снимок изменяемого Set при продолжающемся admission недостаточен.

**Constraints:**
- Сохранить возможность checkpoint/save уже принятой finalization во время release и не вернуть прежний serial-queue deadlock.
- Сохранить owner generation/token fencing, native lock и checkpoint-before-rename.
- Не расширять FIX на CLI/scheduling, native lock, path/platform hardening или другие неизменённые поверхности.
