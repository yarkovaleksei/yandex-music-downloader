### F-001 — Boundary-плагин пропускает path- и alias-specifier-ы, ведущие за пределы workspace-пакетов (relative в node_modules, абсолютный путь, file:, #imports)

**Severity:** medium
**Category:** implementation
**Location:** eslint/boundaries-plugin.mjs:76
**Scenario:** Given Boundary-проход eslint --no-inline-config -c eslint.boundaries.config.mjs в составе yarn run lint и исходный файл в apps/cli, packages/core/* или packages/shared / When файл импортирует модуль по относительному пути, выходящему из workspace-пакетов в node_modules или в корень репозитория, по абсолютному пути, через URL file: или через subpath-alias #... из поля imports / Then resolveTarget возвращает null либо kind external без разрешения пути, boundaries/dependency, boundaries/external и boundaries/bypass молчат, и yarn run lint проходит
**Expected:** Implementation plan шаг 3: alias/relative imports не должны обходить правило; неразрешимые specifier-ы закрываются fail-closed; docs/development.md обещает проверку относительных и deep-импортов. Такие импорты проходят те же проверки (Yandex SDK только в provider по PRN-001, ADR-001 п.1–6, запрещённые модули core/application, чистота shared) либо запрещаются.
**Observed:** lintText с eslint.boundaries.config.mjs (allowInlineConfig:false) даёт messages [] для apps/cli/src/p.ts: import '../../../node_modules/@dvxch/yandex-music/index.js', абсолютный путь в node_modules, 'file:///x/node_modules/@dvxch/yandex-music/index.js', '#sdk', '../../../node_modules/@music-downloader/core-downloader/dist/index.js'; для core/retry: relative в node_modules core-downloader и '#downloader'; для core/downloader: relative node_modules/electron; для shared: relative node_modules/lodash и ../../../eslint/boundaries.config.mjs. Контрольный bare import '@dvxch/yandex-music' даёт boundaries/external. TypeScript-программа apps/cli даёт 0 diagnostics, typecheck этот обход не ловит.
**Impact:** Блокирующий PRN-001 и ADR-001 п.1, п.3, п.5 можно нарушить при зелёных lint и typecheck; docs/development.md заявляет fail-closed проверку, которой нет.
**Fix direction:** В eslint/boundaries-plugin.mjs сделать разбор specifier-ов fail-closed: относительный путь, выходящий из каталога owning package и не попадающий в известный workspace, запрещать отдельным messageId либо отображать сегмент после последнего node_modules/ на имя пакета и прогонять через существующие workspace/external-проверки; абсолютные пути и URL-схемы запрещать в boundaries/bypass; #-specifier-ы разрешать через imports owning package.json либо запрещать. В eslint/boundaries.test.ts добавить негативные кейсы для всех форм и позитивные для локального ./x.js и builtins вне shared. Обновить docs/development.md.
**Fingerprint:** sha256:70c7d3bcca2efe549894b31a4f036d73a654245b542812ae035ac447351b6a1a

**Admissible alternatives:**
- Запретить относительные specifier-ы за пределами каталога owning package и все #-импорты в packages/** и apps/**; запрет поля imports в manifests проверять в consistency.test.ts; зафиксировать как STEP-ужесточение
- Резолвить specifier стандартным Node resolution, классифицировать по realpath, node_modules/<pkg> отображать на внешний модуль; неразрешённое — fail-closed

**Constraints:**
- Не ослаблять существующие правила boundaries/* и независимый oracle ADR-001 п.1–6
- Boundary-проход без type-information и без inline-конфигурации
- Изменения только в Mutation policy STEP-001; ADR/REQ и соседние STEP не менять

**Evidence:**

- Пробы ESLint lintText и in-memory TypeScript program в scratchpad reviewer-а: CLEAN для всех перечисленных форм
- eslint/boundaries.test.ts не содержит этих кейсов; docs/development.md:64 заявляет fail-closed

### F-002 — Запрет I/O-глобалов в packages/shared обходится ambient-объявлением в модуле (declare const process, declare function fetch)

**Severity:** medium
**Category:** implementation
**Location:** eslint/boundaries-plugin.mjs:330
**Scenario:** Given Production-файл packages/shared/src/*.ts; shared собирается с types: [] и lib ES2023 без DOM / When в модуле объявляется declare const process: {...} или declare function fetch(...), затем используются process.env или fetch('u') / Then boundaries/bypass молчит: Program:exit смотрит только globalScope.through и переменные глобальной области; TypeScript тоже не выдаёт ошибок, в runtime используется настоящий глобальный process/fetch
**Expected:** ADR-001 п.5 и plan шаг 3: shared не использует I/O-глобалы и обходы этого запрета; ambient-объявление запрещённого имени в shared падает в boundary-проходе.
**Observed:** lintText: packages/shared/src/p.ts с declare const process + export const x = process.env даёт messages []; declare function fetch + fetch('u') даёт []. Контроль: без declare — boundaries/bypass; declare global { var process } — boundaries/bypass. TypeScript-программа shared даёт 0 diagnostics.
**Impact:** Контракты shared (preload/renderer) могут получить Node/DOM I/O при зелёных lint и typecheck, нарушая ADR-001 п.5; types: [] подталкивает к declare-обходу.
**Fix direction:** В boundaries/bypass для shared сообщать об ambient-объявлениях запрещённых имён (declare переменные, TSDeclareFunction, declare namespace/module) и/или считать глобальными ссылки на переменную со всеми ambient defs. В boundaries.test.ts добавить негативные кейсы declare const|let|var и declare function для process, fetch, window и позитивный кейс для packages/shared/src/web-platform.d.ts.
**Fingerprint:** sha256:9421bf92f96b198b2413ca69aba49996c931f16f8da408182c6da9a85f978313

**Admissible alternatives:**
- Запретить в packages/shared любые ambient-объявления переменных и функций вне allowlist-файла src/web-platform.d.ts и закрепить тестом

**Constraints:**
- Не ломать ambient-типы чистых web API в web-platform.d.ts
- Не ослаблять production-конфигурацию shared и не добавлять I/O-глобалы
- Изменения только в eslint/** и при необходимости docs/development.md

**Evidence:**
- eslint/boundaries-plugin.mjs:323-345 Program:exit учитывает только globalScope.through и globalScope.variables
- Пробы lintText и tsprobe в scratchpad reviewer-а
- boundaries.test.ts не проверяет ambient-объявления
