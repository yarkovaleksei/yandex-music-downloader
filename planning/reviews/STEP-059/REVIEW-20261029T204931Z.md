### F-001 — Выход через sidebar оставляет аватар прежнего аккаунта на открытом Account

**Severity:** medium
**Category:** implementation
**Location:** apps/desktop/src/renderer/Account.tsx:52
**Scenario:** Given Пользователь авторизован, открывает экран Account и дожидается нового аватара. / When Пользователь нажимает «Выйти» в sidebar; api.logout успешно завершён, текущий аккаунт становится null и sidebar отображает состояние без входа. / Then Смонтированный Account не перечитывает account и не очищает avatar: старая фотография продолжает отображаться после выхода. Изменение авторизации в App не меняет api и не передаётся в Account.
**Expected:** Новый аватар текущего аккаунта очищается/инвалидируется после любого штатного выхода или смены аккаунта, включая sidebar; данные прежнего аккаунта не остаются текущим изображением.
**Observed:** Account.refresh/revision и setAvatar(undefined) выполняются только при mount/api change или собственной action Account. App.authenticate обновляет только родительский account; AccountPage получает неизменный api и onChanged обратного направления. Исходный App reproducer подтверждает успешный logout при оставшемся img alt='Аватар аккаунта'.
**Impact:** Нарушены Acceptance 6 и unit5 Ready plan об изоляции аватара после logout/change account. Обычный доступный UI path оставляет фотографию прежней сессии; существующий тест проверяет только кнопку выхода внутри Account.
**Evidence kind:** reproduced
**Evidence source:** node_modules/.bin/vitest run --config .harness/local/tmp/review059-lead/vitest-avatar.config.mjs
**Verification method:** Изолированный Vitest/jsdom App с обычным DesktopApi mock; production не менялся.
**Verification result:** Exit 1, 1 test failed: current account null и sidebar logged-out подтверждены, но img alt='Аватар аккаунта' остаётся вместо ожидаемого null.
**Fix direction:** Передавать Account актуальную авторизацию/ревизию из App либо общий auth invalidation signal и на sidebar logout/change account очищать avatar и инвалидировать его pending result; сохранить независимую загрузку фото. Добавить regression App→sidebar logout при открытом Account.
**Fingerprint:** sha256:05d2daf96096556a5240bf8d13b79e14057f7d9c346bf6be9388e06e32cebc76

**Constraints:**

### F-002 — Поздний account lookup аватара восстанавливает credentials предыдущей сессии

**Severity:** high
**Category:** implementation
**Location:** packages/application/src/application.ts:95
**Scenario:** Given Авторизован A, новый accountAvatar выполняет независимый account-status с credentials A, ответ задержан. / When Пользователь выходит и успешно входит как B, затем приходит прежний account-status A. / Then Provider.getAccount восстанавливает active credentials A; следующий account возвращает A, хотя authenticate подтвердил B и credential store содержит B.
**Expected:** Ответ прежней сессии не меняет текущие credentials и account после logout или успешной смены аккаунта.
**Observed:** Независимый source reproducer через createApplication, настоящий CachedProvider и YandexMusicProviderAuth получил authenticatedId=B, observedId=A, persistedId=B, avatar=null.
**Impact:** Новая сессия B продолжает account/provider операции с credentials ранее вышедшего A; нарушена изоляция текущей сессии.
**Evidence kind:** reproduced
**Evidence source:** /tmp/review059-security/account-race.test.ts
**Verification method:** node_modules/.bin/vitest run --config /tmp/review059-security/vitest.config.mjs
**Verification result:** Независимый security reviewer: exit1, authenticate=B, avatar=null, store=B, следующий account=A; expected B received A.
**Fix direction:** Защитить credential commit в provider.getAccount поколением сессии/актуальностью credentials после await; отбрасывать прежний ответ до изменения active.
**Fingerprint:** sha256:1244432f6e73f10d8dc513b9d20533ba4e66b955a6512c388c1a90a96d0b352c

**Confirmed preconditions:**
- Авторизован A.
- Обычный доступ к UI, delayed account-status из avatar до logout/loginB.
- Host допускает параллельный read-only avatar и auth операции; не требуется renderer compromise.

**Admissible alternatives:**
- Общий session-generation guard account lookup и credential commit.

**Constraints:**
- Сохранить неблокирующие account/logout при optional avatar.
- Не включать avatar network в общую metadata/auth очередь.
- Сохранить provider boundary и safe bytes DTO.

**Evidence:**
- Account.tsx:34–38,58–74: avatar независим, logout/login доступны.
- packages/application/src/application.ts:95 и cached-provider.ts:120–129: новый getAccount вне auth queue.
- packages/providers/yandex-music/src/yandex-music-auth.ts:156–162: поздний ответ безусловно записывает active.
- apps/desktop/src/host/index.ts:38–40 и transport/host-client.ts:41: IPC обрабатывается параллельно.
- /tmp/review059-security/account-race.test.ts:25–36: независимый source reproducer.
