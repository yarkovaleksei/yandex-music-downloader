### F-001 — Одиночный resultPath теряет разные треки коллекции с одинаковыми artist/title

**Severity:** high
**Category:** implementation
**Location:** packages/application/src/adapters/download-files.ts:36
**Scenario:** Given Provider возвращает playlist с двумя available треками разных id, одинаковыми artist/title и mp3 variant; createApplication использует production IO, concurrency=1 и обычный skip policy. / When Клиент вызывает createDownload для всей коллекции. / Then Оба позиционных trackKey получают одинаковый resultPath; первый загружается, второй объявляется skipped, а job возвращает completed с единственным файлом первого трека.
**Expected:** Каждая позиция immutable plan сохраняет собственное содержимое; разные треки с одинаковыми metadata не могут выдавать файл друг друга за existing valid output. Ready plan §3 требует учитывать manifest.destination, trackKey/position и выбранный container при генерации пути.
**Observed:** Реальный public facade probe завершился exit 0 и вернул status=completed; trackKey 1=completed, 2=skipped, samePath=true, opened=[one], written=[1,1,1]. buildTrackLayout вызывается отдельно для каждой позиции и каждый раз строит одиночный путь по artist/title; позиция используется только для partPath.
**Impact:** Обычная загрузка album/playlist молча теряет второй различный аудиотрек и сообщает успешное завершение коллекции.
**Evidence kind:** reproduced
**Evidence source:** Прямой IO experiment текущего публичного createApplication с конкретным обычным playlist и разные bytes на track id.
**Verification method:** node --input-type=module, public createApplication из свежей build output; source adapters проверен на совпадение текущего wiring.
**Verification result:** Exit 0; второй stream не открыт, оба resultPath совпадают, job falsely completed.
**Fix direction:** Генерировать стабильные разные final resultPath для позиций коллекции и коллизий в одном плане, используя существующие core layout/sanitizer algorithms и контекст plan. Сохранить mapping после restart и existing skip/overwrite policy; добавить public facade regression на два различных payload с совпадающими artist/title.
**Fingerprint:** sha256:dcbf8fef064dc25b906366a6a42a8b0a8107ffaca7d76808ab2ea67bde4574a8

**Confirmed preconditions:**
- Оба трека available и имеют допустимый variant.
- Совпадают artist/title; track id и plan position различаются.
- Production final adapter и default skip policy; concurrency=1 исключает недетерминированную race.

**Constraints:**
- Исправление принадлежит STEP-018 application adapter.
- Не дублировать sanitizer/writer algorithms и не менять manifest v1 без отдельного contract основания.
- Не включать future audio validation, tagging или playlist-file генерацию в этот FIX.
