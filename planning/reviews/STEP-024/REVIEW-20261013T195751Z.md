### F-001 — Повреждённый artwork payload прерывает preview вместо повторного получения обложки

**Severity:** medium
**Category:** implementation
**Location:** packages/application/src/cache-payload.ts:265
**Scenario:** Given Успешный public preview создал запись обложки с version=1 и ещё действующим expiresAt; provider продолжает возвращать корректные байты обложки. / When В этой записи payload становится {kind: artwork, value: null} либо отсутствует value и выполняется следующий preview в пределах TTL. / Then decodeArtwork выбрасывает TypeError до fallback; application возвращает DOWNLOAD_ERROR и не вызывает provider.fetchArtwork повторно.
**Expected:** Повреждённая структура payload должна считаться cache miss; действующая обложка повторно получается у provider, а preview завершается успешно.
**Observed:** decodeArtwork проверяет kind, затем без проверки объекта обращается к parsed.value.mimeType. FileCacheStore успешно читает envelope, поэтому его catch не перехватывает исключение decoder.
**Impact:** Одна повреждённая запись обложки делает preview и получение обложки для resolving недоступными до истечения TTL или очистки cache, хотя исходный provider исправен.
**Evidence kind:** reproduced
**Evidence source:** Чтение decoder и bounded public createApplication reproducer с настоящим FileCacheStore.
**Verification method:** Direct invocation exact source decoder и public preview до/после повреждения реального cache файла.
**Verification result:** TypeError подтверждён source decoder; public preview вернул DOWNLOAD_ERROR, provider.fetchArtwork не был повторно вызван.
**Fix direction:** Проверить, что parsed.value является объектом допустимой формы, до чтения mimeType/base64; malformed payload должен возвращать undefined и проходить обычный provider fallback. Добавить regression для null и отсутствующего value через настоящую cache запись/public preview.
**Fingerprint:** sha256:436d9ab9ee607cdd3646952da39544d0c73043950cbd5aaf18bbcacafd70d9fc

**Confirmed preconditions:**
- Повреждённый payload находится в существующем, корректном по version/expiresAt envelope; expiry не наступил.
- Provider override имеет явный namespace и возвращает корректный Track и ArtworkData; cache включён стандартным composition root.

**Admissible alternatives:**
- Сделать decoder boundary безопасным для всех неизвестных структур так, чтобы ошибка чтения конкретного cache payload становилась miss, сохраняя ошибки самого provider.

**Constraints:**
- Исправление внутри packages/application и соответствующих тестов STEP-024.
- Не заменять ошибку provider успешным cache ответом; не расширять scope на unrelated hardening.

**Evidence:**
- planning/tasks/STEP-024.md:113: shape payload проверяется при чтении; повреждённый payload повторно получается у provider.
- packages/application/src/cache-payload.ts:261-272 и packages/application/src/cached-provider.ts:118-123: decoder exception не превращается в miss.
- Direct source check node --input-type=module импортировал cache-payload.ts и вызвал decodeArtwork(JSON.stringify({kind:'artwork',value:null})); exit 0, результат {status:'thrown',name:'TypeError'}.
- Bounded real-filesystem check через createApplication из текущего build: first preview=result; изменена только artwork запись на value:null без изменения expiry; second preview=error, errorCode=DOWNLOAD_ERROR, trackCalls=1, artworkCalls=1. Временный stateDir в .harness/local удалён после проверки.

### F-002 — Смена аккаунта во время cache lookup сохраняет metadata нового аккаунта под ключом прежнего

**Severity:** medium
**Category:** implementation
**Location:** packages/application/src/cached-provider.ts:123
**Scenario:** Given Cache включён; public preview начался под аккаунтом A и исходный getAccount вернул A; исходный MusicProvider переключает текущую session при authenticate. / When Во время асинхронного FileCacheStore.read вызывается public authenticate и session переключается на B; metadata request после чтения cache выполняется уже под B. Затем host снова входит в A и повторяет preview. / Then Metadata B записывается с accountId=A и возвращается как cache hit для A без нового metadata запроса.
**Expected:** Metadata и availability одного аккаунта не должны становиться cache hit другого аккаунта; смена session между account snapshot и provider request не должна загрязнять namespace прежнего аккаунта.
**Observed:** Account ID снимается один раз до await store.read. После await вызывается request у изменяемого provider и его результат без повторного подтверждения session записывается по прежнему ключу. authenticate/logout просто делегируются и не отмечают смену session для активных cache операций.
**Impact:** После обычной смены аккаунта повторный preview A может показывать metadata или availability, полученные у B. Изоляция account ключей по REQ-027 нарушается до TTL/clear; audio методы продолжают live delegation, поэтому обход audio доступа этим экспериментом не заявляется.
**Evidence kind:** reproduced
**Evidence source:** Bounded public createApplication reproducer с контролируемым account lifecycle и настоящим FileCacheStore.
**Verification method:** Public preview под A; после getAccount notification authenticate B; дождаться preview; authenticate A; повторный preview в пределах TTL.
**Verification result:** Current account A получил title B из cache, provider.getTrack вызван всего один раз: {current:'A',first:'B',second:'B',calls:1}.
**Fix direction:** Защитить cache операции от смены session между account snapshot, lookup, provider request и публикацией: при обнаруженной смене не записывать результат под прежним accountId и не обслуживать дальнейший запрос чужой записью. Добавить regression с public preview и authenticate, переключающим аккаунт во время асинхронного lookup.
**Fingerprint:** sha256:63a7121e6300f5bbc598d010476b1a9aa667706a2f86f27526942e0af9cce402

**Confirmed preconditions:**
- Public authenticate может выполняться между live account snapshot и завершением асинхронного filesystem lookup.
- MusicProvider использует текущую session в metadata request; этот lifecycle реализован default Yandex provider и поддерживается официальным providerOverride seam.
- Provider сообщает разные metadata для A/B; для воспроизведения использован title текущего account как безопасный маркер.

**Admissible alternatives:**
- В decorator отслеживать поколение session при authenticate/logout и отменять cache publication операций прежнего поколения, с проверкой фактического account для случая смены исходного provider.
- Подтверждать account после provider операции и выполнять bypass/retry при несовпадении, сохраняя существующий shared/provider contract.

**Constraints:**
- Не менять shared/provider contract вне Mutation policy STEP-024.
- Не кэшировать auth, credentials, варианты, download info или audio stream ради исправления гонки.
- Сохранить live getAccount и диагностику на исходном provider.

**Evidence:**
- docs/requirements/REQ-027-meta-cache.md:15,26: account-dependent metadata изолируются account ключом; записи доступности/вариантов одного аккаунта не используются для другого.
- packages/application/src/cached-provider.ts:109-126: key создаётся до await store.read, request и store.write не проверяют смену account/session.
- packages/application/src/composition-root.ts:78,148: public API использует decorator; authenticate доступен через ApplicationFacade и делегируется тому же provider. Default Yandex metadataRequest читает текущие credentials при начале metadata операции (packages/providers/yandex-music/src/yandex-music-auth.ts:312-325).
- Bounded real-filesystem check использовал public createApplication, стандартный FileCacheStore и допустимый providerOverride с явным namespace. После getAccount(A) public authenticate переключил provider на B; первый preview сохранил title B. После authenticate(A) второй preview вернул title B; captured output {current:'A',first:'B',second:'B',calls:1}, exit 0. Временный stateDir в .harness/local удалён.

**Observed:** В cache.integration.test.ts provider getAlbum/getPlaylist/openAudioStream не вызываются; после TTL проверяется только getTrack; нет second createApplication с прежним schema для disk hit.
**Impact:** PASS существующих тестов не доказывает полный утверждённый scope REQ-027/STEP-024.

**Verification result:** Обязательные сценарии отсутствуют в current test suite.
**Fix direction:** Добавить узкие integration assertions на Album/Playlist/artwork TTL и restart с тем же namespace; отдельный тест вызывает variants/stream дважды и проверяет counters/отсутствие marker в cache.
**Fingerprint:** sha256:3ba1de53ec81ca9c41af95b62908c5b0222d9bbc2b83f42fdcea819f3a6a47fb
