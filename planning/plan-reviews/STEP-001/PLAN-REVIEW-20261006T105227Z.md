## Findings

- N1 [medium/implementation] Шаги 3–4: linterOptions.noInlineConfig: true в boundary-проходе + --max-warnings 0 -> ESLint выдаёт warning на каждую inline-директиву (в т.ч. одобренный `eslint-disable-next-line @typescript-eslint/no-explicit-any -- причина`), npm run lint падает (проверено на eslint 10.12.0). Один вызов `eslint .` не делает два прохода; config второго прохода не в Files. Fix: boundary-проход — отдельный вызов со своим config-файлом (в Files) и CLI-флагом --no-inline-config; lint = два явных вызова; позитивный тест на файле с `-- причина`: errorCount=0 и warningCount=0 в обоих проходах.
- N2 [medium/implementation] Шаги 3,5: `import { type X } from '@music-downloader/shared'` и `export { type X } from ...` в apps проходят allowTypeImports, но при verbatimModuleSyntax tsc выпускает `import {} from ...` (runtime-ребро apps -> shared; ADR-001 п.1/PRN-001). Fix: в boundary-проходе для apps/** включить @typescript-eslint/no-import-type-side-effects (или import-x/consistent-type-specifier-style prefer-top-level), запретить `export {type ...} from` shared; негативные кейсы inline-type import/export; опционально проверка, что apps/*/dist не импортирует @music-downloader/shared.
- N3 [medium/contract] Шаг 3: пустой allowlist value-импортов сторонних модулей действует и на packages/core/*, категория (А/Б) не указана, пути расширения нет (STEP-012..017, 021..023 не могут менять boundary rules; STEP-023 допускает bundled FFmpeg в core/validation, STEP-016 — schema-библиотеку). Fix: отнести allowlist core к (Б) либо ограничить core явным deny-list по ADR-001 п.3 (electron/react/@mui/*, native-модули, @dvxch/*); добавить core-STEP в наблюдения completion report (PROJECT RECONCILE) и зафиксировать в development.md.
- N4 [low/implementation] Шаг 4: no-restricted-syntax (нелитеральный ImportExpression, require/createRequire, import('x').T), import-x/no-relative-packages, no-restricted-globals/properties для shared находятся в основном проходе, где inline-конфиг разрешён; `eslint-disable-next-line no-restricted-syntax` снимает запрет. Fix: перенести все bypass-closure правила в boundary-проход; негативные кейсы с disable-комментарием.
- N5 [low/implementation] Шаги 4–5: type-aware projectService + smoke-тесты в src, исключённые из tsconfig пакета -> `was not found by the project service` на 15 тестах; lintText-кейсы основного прохода на виртуальных src-путях дают fatalErrorCount=1. Fix: исключить test-globs из type-aware блока (или parserOptions.project на tsconfig.test.json); lintText-кейсы основного прохода — вариант конфига без type information либо тест на реальных файлах.
- N6 [low/implementation] Шаг 2: tsconfig include/exclude не поддерживают brace-expansion; test-globs, скопированные буквально, не сработают. Fix: генерировать развёрнутые паттерны для tsconfig, consistency-тест сравнивает развёрнутые множества.
- N7 [low/evidence] Verification называет Node 22.12, но eslint 10.12.0 требует ^22.13 || >=24; typescript latest 7.x вне peer typescript-eslint (<6.1.0); @types/node latest 26.x.
