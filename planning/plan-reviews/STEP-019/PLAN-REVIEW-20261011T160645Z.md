## Findings

- F1 [high] Для exit 6 (чужая живая аренда) в ApplicationApi нет машиночитаемого признака: resume при живом владельце и resume несуществующего job дают одинаковый VALIDATION_ERROR; таймаут владельца — общий DOWNLOAD_ERROR. Исправление: Решение владельца: отдельный STEP application/core вводит стабильный code/details.reason (STEP-019 depends_on) либо правка acceptance REQ-030; для несуществующего JOB_ID сначала getJob.
- F2 [high] bin в apps/cli/package.json меняет запись workspace в yarn.lock (YN0028 при install --immutable), а Mutation policy разрешает только apps/cli/**. Исправление: Добавить Conditional mutation: детерминированное обновление yarn.lock для @music-downloader/cli; добавить yarn install --immutable в Verification.
- F3 [high] Условие завершения resume/retry неверно: queued считается non-running (shutdown ставит возобновлённый job на паузу) либо ожидание job.completed зависает при повторной паузе/отмене. Исправление: subscribe до вызова; конечные статусы completed/completed_with_errors/failed/cancelled/paused/interrupted; опрос getJob до конечного статуса, затем shutdown; тесты на реальном createApplication+providerOverride.
- F4 [high] SIGINT до захвата аренды: pause возвращает interrupted/DOWNLOAD_ERROR, загрузка завершается completed. Исправление: Pause подтверждён только при paused/конечном статусе; повтор после захвата аренды; SIGINT до createDownload не создаёт job; гонку передать владельцу application.
- F5 [medium] Debug-режим со stack (REQ-037) и логи в файл (REQ-029) без пути реализации и владельца. Исправление: Решение: STEP владельца application (log level, файловый sink, редакция) либо уточнение REQ-037/REQ-029.
- F6 [low] Обязательный preview в download добавляет точку отказа и удваивает запросы. Исправление: Брать kind из resolve; preview опционален и не фатален.
- F7 [low] Опции output/quality/overwrite на resume/retry молча теряются. Исправление: Матрица применимости опций; неприменимый флаг → usage error; документировать.
