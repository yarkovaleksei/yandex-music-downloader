## Drift / findings

### F-001 — Коллекция «Мне нравится» отклоняется до обращения к API

Исходная ссылка пользователя возвращает CLI resolve/UNSUPPORTED_URL, exit 3. Resolver и getPlaylist разрешают UUID без префикса и legacy user/kind, но не lk.UUID. Дефект блокирует предоставленную playlist-ячейку.

Read-only исследование установленного SDK на том же аккаунте подтвердило:

- `client.playlist('lk.<UUID>')`: «Мне нравится», reportedTrackCount=148, tracks.length=148.
- `usersLikesTracks(accountId)`: те же 148 треков в том же порядке. Account ID и credentials остаются только в памяти.
- `client.playlist('<UUID>')` без префикса: NotFoundError. Удаление lk не является исправлением.
- Сырой ответ `GET /playlist/lk.<UUID>` принят текущим rawPlaylistSchema; mapPlaylist сохраняет lk.UUID, возвращает 148 available и 0 unavailable. Изменение shared metadata schema по этому evidence не требуется.

Corrective owner — [STEP-051](../tasks/STEP-051.md): распознавание ссылки и admission полного id внутри provider. Production-исправление и скачивание всей lk-коллекции в audit не выполнялись; metadata probe не считается download PASS.

### B-002 — Оставшаяся квалификация и owner go

После F-001 нужны три реальных playlist-цикла. Изменение subject требует evidence на новой принятой ревизии для затронутых условий. Матрица macOS/Windows, platform-specific build/native storage proof, полный checklist brief §47–48 и явное owner go пока pending. STEP-027 не completed; desktop gate закрыт.
